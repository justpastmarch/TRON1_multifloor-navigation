- OBSERVED: 진입점 BAG 1배속 프로세스 재생에서 유효 측위 93개, 지연 중앙값 0.181초 / 95백분위 0.203초 / 최대 0.341초. 점군 유실·IMU 거부·worker 오류 0. 새 결과가 관측된 시점의 지연 통계이며, 결과 사이 모든 제어 주기의 최대 age나 로봇 통신 지연을 보장하지 않는다.

- OBSERVED: 후보 경로를 계속 적용하면 두 BAG은 각각 13.80초·22.80초에 support 제약으로 진행하지 못했다. 비교용 103313은 1.20초에 corridor 제약에 걸렸다. 실제 충돌이나 당시 주행 실패를 관찰한 결과가 아니다.

**Safety 판정:** 보정 부호, 명령 상한, 지연/단절, 취소, 소유권과 모드 전환의 소프트웨어 동작은 시험 범위에서 통과. 실기 자세 유지·전복 여유·RC 우선권 동작은 UNVERIFIED.

**Mobility 판정:** 짧은 첫 구간 평가 통과, 전체 층간 주행 준비 불충족. 계단참 위치와 진입점 정합을 해결하기 전 전체 경로를 활성화하지 않는다.

## 확인된 문제와 수정 후보

### F1. 첫 구간 시험의 모드 전환 중 움직임과 속도 이력

OBSERVED: 기존 `_set_lidar_mode`는 응답을 기다리면서 선택된 구간의 명령을 전송한다. 따라서 첫 구간 시험에서는 명시한 주행 시간 전에도 전진값이 나갈 수 있었다. 출력을 0으로만 바꾸면 내부 속도 이력이 전진값으로 누적돼 전환 직후 가속 제한을 제대로 시작하지 못한다.

후보 수정: 시험 모드 응답 대기 중에는 0만 전송하고, 응답 완료 후 명령 이력을 0으로 동기화한 다음 시험 시간을 시작한다. 응답 대기는 후보 `handoff_sec=3` 이내, 주행은 최대 4초. 전체 기존 임무의 모드 전환 정책은 변경하지 않았다. 응답 실패·측위 만료·취소는 기존 zero/retained STAIR 경로로 종료한다. 새 `reset_command`와 모드 응답 중 zero 전송을 별도 시험했다.

Safety: S3 · Mobility: M1. 실제 사고는 확인되지 않았고, 시험 전 예상치 못한 움직임의 가능성을 코드에서 확인했다.

### F2. 치수만으로 BAG의 시작 위치와 계단 경계가 정해지지 않음

OBSERVED: 현재 후보에서 102101은 횡방향 약 -0.178m, yaw 약 -32.0°인 13.80초에 예측 footprint 경계 검사가 걸린다. 105713은 yaw 약 +90.3°인 22.80초에도 첫 구간으로 남아 있다. 후보의 첫 구간 완료 위치와 기록된 계단참 전환 위치가 맞지 않는다.

INFERRED: 전체 경로를 막는 핵심은 알려준 폭 자체의 부족이 아니라, BAG 시작점·계단참 경계와 후보 경로 원점의 정합 및 footprint/불확실도/예측 여유의 조합이다. 이 자료만으로 각 여유가 물리적으로 얼마나 과한지 확정할 수 없다. 폭을 늘리거나 도착 높이를 낮춰 통과시키지 않았다.

후보 진입 정렬은 초기 roll/pitch를 측정값으로 보존하고 위치·수평 방향만 정렬한다. 완전한 단위 자세를 진입 자세로 넣어 중력 방향까지 바꾸는 잘못된 오프라인 가정을 수정했다. 그럼에도 위 전체 경로 실패가 남았다.

Safety: S2 · Mobility: M3. 다음 과제는 같은 원본 점군에서 첫 단·계단참 경계를 경로 좌표계에 연결하고, 두 BAG 각각의 시작 자세를 그 기준에 정합하는 것이다. 보정 이득을 더 키우는 것으로 이 좌표 문제를 해결할 수 없다.

점수는 이번 검증 내 상대 척도다. S0 영향 없음, S1 진단/간접 영향, S2 제어 여유 손실 가능, S3 예기치 않은 움직임 가능, S4 중대한 직접 위험. M0 영향 없음, M1 일시 영향, M2 부분 구간 차단, M3 전체 임무 차단, M4 이동 기능 전반 불능.

## 후보 경로의 근거와 제약 ledger

`config/stair_lidar.yaml`은 오프라인 후보이며 `commissioned: false`다. `configured: true`는 후보 설정 로딩을 위한 값이고 실기 검증 완료를 뜻하지 않는다. 정상 임무는 계속 거부된다. 공개 action의 명시적 phase_test 경로만 미검증 첫 구간을 최대 4초 허용한다. `Feedback.arm(phase_test=True)`는 내부 함수로서 자체 duration/phase 인증을 하지 않으며, Supervisor가 그 제약을 검증한다.

| 항목 | 값/근거 | 판정·한계 |
|---|---|---|
| 본체·센서 | 사용자 확인 0.45×0.45m, 센서 중심 XY, +0.18m, pitch +5° | OBSERVED: 사용자 제공값을 반영. 별도 실측 오차 범위는 없음 |
| 계단·계단참 | 사용자 확인 폭 1.23m, 가로 2.70m, 전후 1.48m | OBSERVED: 제공값. 구조 경계의 BAG 좌표는 별도 정합 필요 |
| 높이·길이·진입 자세 | 첫 계단 경계 x=2.8m, 높이 1.55m, 전체 높이 3.25m 등 BAG 기반 후보. 시작 몸체 중심 x=-0.45m | INFERRED/UNVERIFIED: 실측 경계나 도착 기준으로 확정하지 않음 |

| 속도·가속도 | v≤0.15m/s, w≤0.20rad/s, 가속도≤0.15m/s², 각가속도≤0.30rad/s² | TUNE: 초기 시험 상한. 바퀴 응답·슬립·등판 능력 미검증 |
| 보정 이득·deadband | yaw 0.6, lateral 0.35, yaw deadband 1°, lateral 2cm | TUNE: 보정 부호와 연속성 검증. 실제 보정 강도/성공률은 미검증 |
| 지연 | warn 0.5초 / expire 0.9초 / recover 표시 2초 | TUNE: 정상 입력 지연 시험 통과. warn에서 새 단계 진행 보류, expire에서 zero. 무기한 추측 주행 아님 |
| 자세 | roll 20°, pitch 45° | UNVERIFIED: 초기 시험용 envelope, 실제 안정 한계 아님 |
| 완료·대기 | 높이 15cm, 위치 on/off 10/5cm, yaw 5°, dwell 0.6초 등 | UNVERIFIED: 전체 도착 경계 불일치가 남음. RViz FINAL ARRIVAL 표시는 사용 안 함 |
| 실행·복구 | 첫 구간 ≤4초, 응답 대기 ≤3초, 종료 zero, STAIR 유지 | NARROW: 미검증 경로의 시험 범위 한정. 전체 임무는 commissioned=false로 차단. 사용자 RC 회수 가능 확인을 근거로 함; zero가 물리적 자세 유지라는 뜻은 아님 |

위 제약은 기존 Supervisor 내부에 적용하는 후보이며 신규 운영 노드는 없다. 실시간 영상 스트림을 전제하지 않는다.

## 재현·배포·정리

- `run_units.py`, `run_pytest.py`, `run_ros_checks.py`, `check_recorded_control.py`, `check_stream.py`와 JSON/XML 결과를 보존했다. ROS 테스트는 localhost:11439의 격리 master와 가짜 transport/관찰 전용 노드로 수행했다.
- 원본 BAG 재계산은 기존 `replay_lidar_tracking.py`와 각 원본 `spec.json`을 사용했다. 103313은 수치 회귀 비교용이며 사용자 승인 주행 기준으로 승격하지 않았다.
- 최초 전체 unittest discovery는 ROS 의존 테스트와 Python 환경 의존성이 섞여 유효한 종합 결과를 내지 못했다. ROS 테스트를 격리하고 pytest 함수형 테스트를 별도 실행했으며 최종 숫자는 정정 후 실행만 센다.
- `candidate/`는 검증한 코드 스냅샷, `candidate.patch`는 기존 운영 코드 대비 검토용 차이다. 운영 코드에 적용하지 않았다. 시험 설정도 운영 설정으로 복사하지 않았다.
- `workspace-check.json`: 감사 전후 production Git 상태 동일, 확인한 production Python/config 파일 해시 변경 없음. 원본 BAG 및 sources/ 미수정.
- 임시 ROS master/worker/test 프로세스를 종료했다. ROS 임시 로그·홈과 pytest 임시 디렉터리는 필요한 XML 결과를 보존한 뒤 제거했다. 분석 스크립트·후보 설정·결과·요약 로그는 재현을 위한 최종 산출물로 유지한다.

## 검증 독립성 점검

mandela: 기존 궤적과 재계산의 일치는 동일 알고리즘·동일 센서 자료의 재현성이다. 이를 정확도 검증으로 해석하면 Shared hallucination에 해당한다. 후보 경로에 같은 BAG을 대입한 결과도 실제 폐루프 결과가 아니다. 물리적 정확도에는 외부 기준이, 제어 성능에는 새 명령에 대한 실기 반응이 필요하다.

shower 독립 검토 지적을 반영해 첫 4초 통과를 물리적 시험 안전성으로 표현하지 않았고, 3초 모드 응답 제한·4초 주행 제한·내부 API 인증 범위·배포 여부를 명시했다. ssotize 읽기 점검: 기존 route-evidence.json의 코드 제한 문구와 이전 구현 보고서는 과거 스냅샷이며 현재 판정은 이 문서와 결과 JSON을 기준으로 한다. 과거 기록을 소급 수정하지 않았다. 제품 중립성 주장이 없어 detool은 적용하지 않았다.
