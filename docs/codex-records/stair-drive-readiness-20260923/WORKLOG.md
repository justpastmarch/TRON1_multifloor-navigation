# 3→4 계단 주행 준비

Understood as: 사용자가 이미 제공한 치수와 기존 녹색 LiDAR 추적을 유지하며 시작 좌표 연결·불필요한 제어 차단·실기 시험 설정을 기존 Supervisor 내부에서 구현한다. 과거 가정 경로의 실패를 실제 주행 성공으로 포장하지 않는다. 새 ROS 노드와 임의의 실기 이동은 추가하지 않는다.

계획: 출발 관측만 사용한 정합 검증, 경계 내 가능한 명령 선택, 단계 접합 검사, WebSocket 단위 확인, 명시적 현장 시험용 설정과 RViz/기록 절차, 회귀·BAG·설정 검증.

기준: production 전체 git-owned 파일 해시와 기존 Git 상태를 baseline.json에 보존했다. 후보 사본에서 수정·검증 후 변경 전 해시가 일치하는 파일만 반영한다.

## 완료 상태

실제 저장소 21개 파일 반영. 기존 LiDAR 추적 코어/IMU 보정, 미션·층·move_base 노드, ROS 메시지는 변경하지 않음. 지정 진입점 preview/run, bound-ticket 시험 소유권, 감속 대안/연결 영역, RViz 동일 시각 점군, 별도 3→4 시험 설정과 실행 환경을 구현함.

149개 단위 시험, 독립 기하 729건 무불일치, ROS 경계 5개+실제 추적 observe 1개, 합성 preview/run/취소, 격리 catkin build/install, 반영 후 설정 검사 통과. BAG 재평가는 기존 차단 두 곳 개선을 보였으나 다음 경계 실패와 수동 궤적 한계로 실제 완주 증거가 아님. 출발 2초 정합은 복수 후보로 갈려 자동 진입 확정에 쓰지 않음.

임시 863개 파일(41,052,204bytes), 시험 프로세스 정리. 정리 명세 cleanup.json. 기존 작업/캐시 유지. 생산 프로세스 재시작 및 물리 주행 명령 0. 실제 실행은 docs/stair-drive-readiness-20260923/RUNBOOK.md. 다음 시작점은 로봇 지정 배치에서 preview 테두리와 점군 확인 후 첫 flight 시험. 자동 임의 진입 측위·물리 3→4 완주·NAV/층 전환 연결은 미완료. 전체 저장소 감사 완료를 의미하지 않음.
