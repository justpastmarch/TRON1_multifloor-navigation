# LiDAR 개선 전후: 독립 영상 3개

사용자가 요청한 비교는 같은 두 BAG을 세 조건으로 각각 재생한 총 세 개의 영상이다. 각 영상 안에서 102101 → 105713 순서로 두 기록을 보여준다. 화면 분할 없이 한 번에 한 조건만 표시한다.

**이 파일은 BAG에서 추출한 실제 점군·측위 결과의 3D 재구성 영상이다. RViz 프로그램 화면을 직접 녹화한 것은 아니다.** 로봇과 연결하거나 명령을 보내지 않았다. 원본 BAG과 운영 코드는 변경하지 않았다.

## 영상과 조건

1. `01-original-floor-aligned.mp4`: 당시 저장된 기존 GICP 궤적에 고정 강체변환 `T_new(0) · inverse(T_old(0))`을 왼쪽에서 곱한다. 각 BAG마다 별도의 고정 변환을 한 번 정한다. 두 초기 위치는 모두 0이며, 시작 회전행렬 전체를 공통 초기 자세에 맞춘다. 이는 독립 측정한 절대 yaw 정렬이라는 뜻은 아니다. 기존의 상대 이동·회전과 정합 성공/실패 기록은 보존한다. 당시 최대 평면을 바닥으로 취급해 발생한 초기 기울기만 공통 중력 좌표로 바꿔 보여주는 조건이다. 과거 실패를 재계산하거나 의도적으로 확대하지 않는다.
2. `02-floor-initialization-only.mp4`: 보존된 기존 `registration_core.py`와 기존 정합 조건을 사용하되, 초기 자세만 최종 개선본의 첫 중력 자세로 바꿔 재계산한다. gyro 회전 예측 없이 마지막 성공 자세를 다음 정합 초깃값으로 사용한다. 실패하면 기존 코드처럼 이전 위치를 반복한다.
3. `03-improved-gyro-gicp.mp4`: 이미 보존된 최종 개선본 CSV를 그대로 사용한다. 영상에 맞추기 위한 추가 튜닝이나 궤적 보정은 없다.

'두 센서' 비교가 아니라 **같은 LiDAR 기록에 대한 세 처리 조건**의 비교다. 이번 영상에는 FAST-LIO나 wheel odometry 궤적을 포함하지 않는다. 초록색은 모두 GICP 계열 LiDAR 측위 결과다.

## 공통 표시 규칙

- 1600 × 1000, H.264 MP4, 10 fps, 약 1배속. 원래 약 5 Hz인 측위 프레임을 반복 표시하며 중간 궤적을 보간하지 않는다.
- 각 BAG에서 세 조건의 카메라 위치·각도·축척이 같다. 각도는 기존 RViz 설정의 yaw 0.78 rad, pitch 0.48 rad를 참고했지만 직교 투영이므로 RViz 원근 화면과 픽셀 단위로 같지는 않다.
- 카메라 중심과 축척은 세 결과 전체의 범위를 함께 사용해 한 번 정한 후 고정한다. BAG이 바뀔 때는 해당 BAG의 공통 카메라로 전환한다.
- 초록 선은 누적 궤적, 회색은 각 스캔 시점의 해당 조건 추정 위치·회전으로 배치한 현재 및 최근 15개 스캔, 연노랑 선은 LiDAR 좌표계의 +X 추정 방향이다. 연노랑이 검증된 로봇 전진축이라는 뜻은 아니다.
- 점군은 표시 부하를 줄이기 위해 저장된 voxel 점군에서 한 점씩 건너뛰어 표시한다. 이 표시용 생략은 정합 계산에 사용하지 않는다.
- 화면에는 동일한 측정 경과 시간, 프레임 번호, 정합 상태, 마지막 성공 이후 경과 시간, 누적 실패 횟수, 추정 좌표를 넣었다.
- 실패 프레임에서도 이전 자세로 현재 점군을 배치한다. 이는 기존 출력의 문제를 드러내기 위한 표시이며, 실패 점군이 올바르게 정합되었다는 뜻이 아니다.
- 각 BAG 앞 2초, 끝 4초를 정지 화면으로 유지한다. 마지막 프레임까지 보여주며 별도 도착 성공 판정을 추가하지 않는다.

분모는 초기화 프레임을 제외한 정합 횟수다. 첫 BAG은 총 500프레임 / 99.800초, 두 번째는 총 340프레임 / 67.801초의 센서 시간 구간이다. 바닥 초기화만 수정한 결과는 이번에 직접 계산했다. 기존/최종 수치는 보존된 CSV에서 읽었다.

**바닥 정렬만으로 추적 문제가 모두 해결되지는 않는다.** 다만 위 숫자는 알고리즘 자체의 정합 허용 조건에 따른 성공/실패다. 개선본에서 회전 허용 조건의 기준 자세가 gyro 예측으로 달라지므로, 실패 0회를 절대 위치 오차 0 또는 실장비 주행 성공으로 읽으면 안 된다.

## 재현성과 한계

- 원본 BAG에서 과거 추출·검증한 선택 스캔 캐시를 재사용했다. 헤더 타임스탬프가 기존/최종 CSV와 모든 프레임에서 같은지 확인했다.
- 새 바닥 초기화 실험은 캐시의 float32 voxel 좌표를 float64로 변환해 계산한다. 보존된 원래 실행과는 저장 정밀도가 다를 수 있다. 이 실험을 raw 데이터 전 경로가 bit-identical한 재실행이라고 주장하지 않는다.
- 초기 자세는 보존된 최종 결과의 첫 자세를 사용했다. 그 자세는 초기 IMU 중력 방향에서 얻은 것이며, 최종 위치나 전체 경로를 맞춘 변환이 아니다. 이번 바닥 초기화 실험은 IMU 초기 자세를 공유하는 ablation이지 외부 독립 정답 검증이 아니다.
- 강체 정렬 조건은 그 자체로 기존 궤적의 길이·상대 회전을 바꾸지 않는다. 좌표축에 대한 개별 x/y/z 수치만 바뀐다.
- 회색 점군은 각 알고리즘 출력으로 만들어진 지도이며 외부 정답 지도가 아니다. 독립 위치 정확도 검증에는 실측 위치·방향 또는 별도 기준 장치가 필요하다.
- 구체적인 입력 경로·해시는 `102101-method.json`, `105713-method.json`, 카메라·프레임·챕터 시간은 `old-video.json`, `floor-video.json`, `new-video.json`에 남긴다.

계산: `prepare.py`. 영상 생성: `render_single.py`. 결과 검증과 임시 산출물 정리는 `verification.json`에 기록한다.
