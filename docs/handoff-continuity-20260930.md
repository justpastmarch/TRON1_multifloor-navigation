# NAV→계단 인계 연속성 수정 · v14

2026-09-30. **운영 원본 코드·설정 반영 및 오프라인 검증 완료. 실행 중인 로봇 스택 적용은 미완료**다. 마지막 확인에서 miniPC SSH/센서 서비스는 연결됐으나 TRON 제어 포트 연결은 실패했고, 현재 LiDAR raw/odom의 최신 쌍도 수신되지 않았다. 연결 오류로 남아 있던 v13 실행기는 정상 종료했다. 다음 실행은 v14 소스를 읽지만 아직 실제 실행 상태를 검증하지 않았다. 코드 변경이 자동으로 실행 프로세스에 반영되지는 않는다. 실제 주행 목표나 계단모드 명령을 보내지 않았다.

## 바뀐 동작

첫 계단과 맞닿는 경계를 통과 가능한 내부 경계로 처리한다. 기존의 `entry_polygon` 단독 검사를 진입 평지와 첫 상승 구간의 합집합으로 바꿔, 첫 단에 가까워서 몸체 앞부분이 경계에 걸친 경우를 거부하지 않는다. 옆·뒤의 실제 외곽 여유 12cm는 유지한다. 이 변경은 3F→4F와 5F→RF 운영 설정에 적용된다. 새로운 ROS 노드나 상태는 추가하지 않았다.

진입은 첫 단 근방이어야 하고 측정 높이는 출발 높이에서 15cm 이내여야 한다. 합집합이 된다고 중간 상승 구간에서 출발 가능한 것으로 인정하지 않는다. 첫 단 방향으로의 중심 진행은 첫 단 경계+불확실성 포함 여유 이내로 제한한다. 이것은 첫 단 앞의 대기 간격 요구가 아니며, 잘못된 계단 중간 시작을 구별하는 제한이다. 평면상의 몸체 포함은 실제 접촉 동역학의 검증이 아니다.

ALIGN에서는 정확한 45cm 대기점으로 되돌아가지 않는다. 허용 영역 안에 있으면 현재 전후 위치를 사용하고 방향 오차 10° 이내에서 상승 제어로 넘긴다. 횡방향 보정은 기존 상승 제어기가 수행한다. 독립 ALIGN 테스트에도 같은 영역 기준을 사용하되, VERIFY를 거치지 않았다면 관측 안정 구간을 확인한다. 모드 ACK 대기 중에는 0 명령을 유지하고 ACK 후 기존 VERIFY_ENTRY/ALIGN이 실행된다. 0 명령은 기계적인 자세 고정을 의미하지 않는다.

NAV 자체의 도착 범위 25cm·11.46°·0.5초는 보존했다. 이번 세 시도에서 이미 이 범위를 통과했기 때문이다. 범위를 50cm 원으로 무조건 넓히면 실제 계단 옆에서 NAV를 너무 일찍 끝낼 수 있다. **그 후의 지도 인계 검사를** 50cm·30°의 대략적인 위치 확인으로 완화하고, 실제 계단과 몸체 관계는 LiDAR가 판정한다. 이 역할 차이는 의도된 것이다.

LiDAR 운용에서만 인계 AMCL age를 0.5→1.0초, x/y 공분산을 0.05→0.10, yaw 공분산을 0.10→0.15로 조정하고 정지 이후 표본을 3개→1개 요구한다. 같은 층·지도 세대·정규화된 자세·최신 odom 조건은 유지한다. 관측 대기는 2→4초다. LiDAR off/observe 모드에는 기존 인계 정책을 사용한다. 실제 LiDAR에는 여전히 별도 최신성·매칭·몸체 영역 검사가 있다.

순간 odom 한 표본으로 정지를 선언하거나 거부하지 않는다. 최근 0.3초의 **절대 이동 속도·절대 회전 속도를 시간 가중 적분**해 각각 평균 0.06m/s·0.12rad/s 이내인지 본다. 반대 방향의 움직임을 상쇄하지 않는다. 최소 0.25초 관측, 최대 0.15초 측정 공백·나이를 요구한다. 창 안의 큰 값(0.12m/s·0.70rad/s 초과), 마지막 값(0.08m/s·0.20rad/s 초과), 오래되거나 역행·중복된 측정 시각은 통과하지 않는다. 이 조건은 완전 정지가 아니라 전환에 허용하는 작은 잔류 움직임의 계약이다.

인계 대기와 토큰 재검사는 같은 판정 코드를 사용한다. 순간 실패 시 4초 안에서 새 관측을 받고, 위치 갱신 RPC가 한 번 실패해도 즉시 미션을 끝내지 않는다. 토큰 수명은 매칭 3초+새 LiDAR 대기 1초+재관측 4초+일정 여유 2초를 포함한 10초다. 재관측을 마친 후에도 만료를 다시 확인한다. 토큰은 일회성이며 경로·방향·소유권에 묶인다. 센서의 측정 시각과 수신 시각을 구분해 늦게 받은 센서를 새 관측으로 둔갑시키지 않는다.

진입 geometry 거부에는 body_xyz, 높이 오차/허용값, supported 여부가 표시된다. 기존의 의미 없는 `use from_entry` 안내 대신 원인을 직접 확인할 수 있다.

## 작업 정리

기존 worktree 변경을 되돌리지 않았다. 이번 작업은 운영 코드·설정·회귀 테스트·보고서를 추가 수정하므로 감사 전후 Git 상태가 동일한 작업이 아니다. 기준 상태는 git-before.txt에 기록했다. 최종 테스트 로그·결과 XML·BAG 판정 JSON은 검증 산출물로 보존했다. 임시 ROS master와 모의 노드는 종료했고, 임시 ROS_HOME 로그/캐시와 /dev/shm/tron1-handoff-v14-20260930의 모의 BAG 6개를 제거했다. 최초 혼합 테스트 실행기는 정상 종료 신호에 반응하지 않아 해당 PID만 확인 후 강제 종료했다. 기존 실제 BAG은 수정하거나 삭제하지 않았다.
