# 계단 관측 기반 주행과 자동문 UI · v17

## 현재 동작

OBSERVED: 운영 정책 `2026-10-01-observed-flight-v17`에서 3F→4F 및 5F→RF 상승 구간은 `flight_command_policy: observed_feedback`을 사용한다. 같은 LiDAR 관측의 차체 위치·자세로 지지영역을 검사하고, 해당 방향과 중앙선 오차로 제한된 조향을 계산한다. 최신 IMU의 각속도 감쇠 기여는 기존 ±0.05 상한을 유지한다. IMU로 진전시킨 방향은 진단에 남기지만 상승 조향 오차나 현재 차체 경계 판정에 섞지 않는다.

OBSERVED: 미검증 입력-속도 모델의 미래 경로 불일치가 생산 상승의 후보 선택·재관측·미션 종료를 결정하지 않는다. 예측은 기존 비동기 shadow 진단으로 남는다. 직접 관측한 지지영역/anchor 여유, 자세 한계, 센서 만료·epoch, 통신과 조종기 인터럽트, 높이와 단계 완료 조건은 기존 경로로 검사한다. 평지 NAV·계단참 회전·옥상 우측 회전·도착 유지의 제어 경로는 그대로다. 새 ROS 노드나 FSM 상태를 추가하지 않는다.

OBSERVED: 상승 입력은 기존 내부 0.55(전송 정규화 전진 1)까지 기존 가속도 제한 0.15로 증가한다. 계단참 저속과 각속도 상한 0.2를 유지한다. sensor `warn_sec`를 넘으면 가속하지 않으며, 만료된 입력은 기존 유한 재관측 예산 동안 0을 보낸다. 0 입력이 물리적 자세 유지를 뜻하지 않는다. 비생산/구형 route는 기본 `prediction_gated` 정책을 유지해 호환한다.

## 기록된 중단과 검증

Finding F1 / OBSERVED / Safety S2 · Mobility M4: 기존 LiDAR 중심을 최신 IMU 방향으로 회전시킨 가설 차체의 여유 부족이 실제 미션 실패가 됐다. 직전 BAG의 LiDAR 차체 여유는 10.754cm, 혼합 가설은 9.441cm로 anchor 10cm 기준에 5.6mm 부족했다. 실제 물리적 여유는 UNVERIFIED다. v17은 현재 차체 판정을 관측 시각에 통일하고 미검증 예측으로 생산 상승을 종료시키는 경로를 분리했다.

OBSERVED: 같은 BAG에서 전체 자세·sequence가 있는 98개 상승 관측과 보존된 first_fault 1개를 재평가했다. v16은 기록된 pending recheck와 기존 0 출력을 마지막 검사에 복원했을 때 동일한 fault를 재현했다. v17은 같은 고정 관측에서 자신의 명령 이력을 유지하며 99개 검사 모두 fault/전진 0 없이 통과했고, 마지막 내부 전진 0.55를 유지했다. 10Hz debug는 중간 제어 tick 전체를 담지 않으므로 이 비교를 정확한 폐루프 재생이라고 부르지 않는다. 자세가 부분적으로만 있는 debug 행은 제외했다.

mandela 검토: 이 검증은 기록된 추정값에 대한 소프트웨어 판정 비교다. 수정된 명령으로 새로운 센서 궤적을 생성하지 않으며 외부 위치 정답이 없다. 따라서 실제 여유, 완주 확률과 성능 개선은 UNVERIFIED이며 새 실주행 BAG와 운전자 관찰로 확인해야 한다. 같은 데이터에서 임계값을 통과한 것을 실제 안전/완주의 정답으로 채점하지 않는다.

## 자동문

OBSERVED: 기존 mission-manager 내부의 UI HTTP 서버에 `console_door.py`를 연결했다. 신규 ROS 노드·FSM·로봇 명령 경로를 만들지 않았다. 생산 5F→RF 주행의 `ROOFTOP_TURN`에서 중앙 도착 waypoint(π)가 끝나고 우측 회전 waypoint(π/2)를 관측하면 사용자가 지정한 HTTPS trigger에 실제 GET 요청을 보낸다. 첫 요청 즉시, 이후 20초 간격으로 반복한다. 브라우저를 닫아도 UI 서버가 실행 중이면 반복한다.

OBSERVED: 기존 EXIT_CONFIRM의 지지영역·최종 높이·모든 상승 구간 완료가 확인되거나 확인된 현재 층이 RF READY가 되면 반복을 끝낸다. 사용자는 `문 통과 완료 · 반복 종료`로도 종료할 수 있다. 중단/정지/일시적인 상태 수신 상실 중에는 통과 중인 문을 유지하기 위해 이미 시작한 반복을 계속한다. UI 서버 종료 시 반복은 종료한다. 종료는 닫기 요청이 아니며 이미 예약된 요청 하나는 종료 버튼 이후 시작하거나 끝날 수 있다. 종료 API가 네트워크 요청 취소 완료를 보장하지 않는다.

사용자 제공 계약: trigger 1회가 60초 개방을 유지한다. 이 장치 동작은 이번 개발에서 실제 요청으로 확인하지 않았다. HTTP 성공은 물리적 문 개방 확인이 아니며 UI도 문 상태 미확인으로 표시한다. 네트워크 실패는 UI에 표시하고 다음 주기에 재시도하며 주행 FSM을 차단하지 않는다. 20초 주기는 서버/네트워크가 정상 동작할 때의 일정이며 통신 장애에서 개방을 보장하지 않는다.

OBSERVED: 복귀 시 현재 층 RF에서 UI의 `복귀 문 열기`를 누르면 문 요청만 시작하며 20초 반복한다. 문 통과 완료 버튼 또는 5F READY 확인으로 종료한다. 향후 기존 하강 route의 telemetry에도 자동 시작 hook이 있다. 현재 자동 하강 및 사진 순회·복귀 미션은 아직 연결/commissioning되지 않았다. 이번 변경이 이를 구현했다고 주장하지 않는다. 미리보기·NAV·3F→4F·실제 주행 없는 화면 열기는 문 요청을 보내지 않는다. UI 테스트(녹화 포함)와 주행만 버튼, 기존 CLI의 RUNNING phase test가 실제 5F→RF 우측 회전 상태를 발행할 때 모두 문 요청을 보낸다. 오래된 상태와 새 복귀 요청 간 경쟁은 generation 검사로 배제하고, 반복 worker 오류를 표시하며 재시도한다.

Finding F2 / OBSERVED(연동 구현), UNVERIFIED(실제 문) / Safety S1 · Mobility M2: 문 요청이 생산 동작에 연결되지 않았던 누락을 UI에서 보완했다. 문 열림 센서가 없으므로 물리적 통과 가능성의 보증은 아니다. 인증 토큰·동일 출처 규칙을 기존 UI POST와 함께 적용한다.

## 적용과 실행

운영 코드/설정과 단위 테스트를 배포한 뒤, 임무·녹화가 없고 사용자 확인한 평지 상태에서 기존 실행기를 재시작한다. live `/api/state`에서 LiDAR 정책 v17·5F READY·Supervisor NAV·door_control 대기와 중복 RAW 제외식을 확인한다. 사용자는 `층 이동 → 옥상 도착점 → 테스트 시작 · 녹화 포함`으로 기존 NAV/계단/Floor 흐름을 실행한다. 주행은 자동으로 시작하지 않는다. 원본 RGB/센서/조이스틱 기록을 보존하고 중복 RAW 녹화 제외도 유지한다.

변경/검증 artifact: before snapshots·hash, changes.patch, regression 결과, replay-summary.json·의사결정 trace, runtime 전후. 기존 dirty worktree를 되돌리지 않는다. mock 문 요청만 검사했으며 개발 중 실제 문 요청·주행·BAG replay ROS process를 생성하지 않았다. 임시 테스트 HTTP 서버는 각 검사에서 종료한다.
