# 5F 계단 진입 주행성과 재시도 개선

## 적용 완료한 변경

사용자가 확인한 첫 단~뒤 벽 1.5m 평지를 기준으로 5F 진입 구역의 뒤쪽 경계를 -1.0→-1.5m로 보정했다. 양옆·전방 경계와 12cm 유효 여유는 유지했다. 구역은 지지 가능한 바닥의 모델이며 화분 등의 장애물이 없다는 보증은 아니다.

자동 미션도 계단 모드 전환 전 전체 진입 footprint·높이를 검사한다. 미리 실패하면 NAV 소유권을 유지하여 다음 시도가 `supervisor does not own NAV`로 막히지 않는다.

모드 전환 후 실패한 경우에는 VERIFY_ENTRY/ALIGN에서만 자동 평지 복구를 시도한다. 같은 epoch의 최신 정상 관측, 첫 단 이전에 완전히 놓인 몸체, 5cm 이내 높이 차, 10도 이내 자세, 두 관측 이상의 낮은 실측 이동 속도, 최신 중립 조이스틱을 확인한다. 이 조건은 주행 시작 조건을 추가하는 것이 아니라 자동 WALK 전환이 가능한지를 판단한다. 이미 상승 단계에 들어갔거나 센서가 오래됐거나 실제 이동 중이면 자동 전환하지 않는다.

복구는 기존 WebSocket 소유자가 0 명령과 mode ACK/status 확인을 수행한다. 응답 후에도 위치·조이스틱 조건을 재검사하고, 오래된 NAV 명령을 삭제하며 ownership epoch를 올린다. ACK나 조건 확인 실패 시 NAV에 제어권을 넘기지 않는다. 소프트웨어 STAIR 소유권 유지가 물리 로봇의 STAIR 모드 유지를 보증하지는 않는다. 통신 실패·중간 조건 상실은 기존 명시적 인계 경로가 필요하다.

## 실행 상태

사용자의 명시적인 승인 후 기존 물리적 인계 서비스를 통해 WALK/NAV 복구를 확인하고 기존 스택을 정상 재시작했다. 주행 목표와 비영 속도 명령은 보내지 않았다.

OBSERVED: 실행 설정 SHA256 `e085960a25488fede72007de0ce7b97afeed082f8c39b2add7be5dfe486279a7`. 현재 원본 점군의 정합 및 진입 footprint/높이 검사 통과. 계산 위치 (-0.6139,0.0697,-0.0047)m, yaw 8.94도. 이 값은 정합 기준 좌표 추정치이며 독립 실측이 아니다. 기하 검사는 동기화 표본의 정적 검사이고, 실시간 freshness는 실행 상태에서 별도로 확인했다.

OBSERVED: 5F auto localization READY, supervisor NAV/connected, RF 경로 계획 can_start=true와 blockers=[] 확인. `live-entry-check.json`, `live-state.json`, `live-plan.json`에 근거를 보존한다. 실제 계단 주행은 사용자 UI 시작을 기다린다.

제어 UI http://127.0.0.1:8765/ 를 새로고침하고 현재 층 5F, 목적지 stair_rf_landing을 선택한 뒤 테스트(녹화 포함) 버튼으로 시작한다. 화분과 실제 주행 경로의 간섭은 확인되지 않았으므로 이번 구역 보정이 장애물 회피 기능의 개선을 뜻하지는 않는다.

## 검토·보존

독립 cold read의 이동 중 모드 해제 가능성 지적을 반영하여 낮은 실측 속도를 복구 조건에 추가했다. 전송 코드는 요청별 응답 상관관계, 취소, 제한 시간 및 WALK 상태 확인을 이미 구현한다. 실장비 ACK 유실/화분 회피/전체 RF 완주는 검증하지 않았다. 기존 작업 변경은 보존했다. 변경 직전 코드·설정 사본과 카메라 프레임은 분석 근거로 이 폴더에 보존한다. 임시 편집 스크립트는 제거한다.
