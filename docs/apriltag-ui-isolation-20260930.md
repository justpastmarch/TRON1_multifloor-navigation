# AprilTag 오류 격리 — 2026-09-30

기존 실행에서는 AprilTag 노드의 zarray_size assertion 뒤 /tag_detections 수신 검사가 실패하여 run.sh가 UI와 NAV를 포함한 전체 로컬 스택을 정리했다.

태그 스트림과 태그 freshness를 전체 스택 시작의 필수 조건에서 제외했다. scan/odom/TF 검사는 유지한다. 태그 검출 노드는 기존 respawn=true, respawn_delay=3 설정으로 복구를 시도한다. UI는 설정된 tag_topic의 최근 수신 시각, 메시지 시각, 검출 개수를 표시한다. 빈 검출 배열을 수신한 것과 목적 층 태그 확인을 구분한다. UI의 태그 표시는 안내이며 별도 주행 차단 조건을 추가하지 않는다. 서버 단절 안내에는 실행 창 확인 방법과 화면 단절이 로봇 정지 확인은 아니라는 설명을 추가했다.

층 도착 판정 코드는 변경하지 않았다. 따라서 태그 오류를 무시하고 층 도착 성공을 만드는 변경은 없다. detector의 assertion 자체를 고친 것은 아니다. 반복 오류가 지속되면 태그 기반 도착 확인은 여전히 불가능하다.

검증: 콘솔 19개와 HTTP 7개 기존 테스트 통과, JS 및 shell 구문 검증, XML 검증, 태그 필수 시작 검사 제거와 detector respawn 설정 확인. 실차에서 detector를 강제 종료하거나 로봇 명령을 보내지 않았다. 적용은 기존 실행 종료 후 TRON 실행 아이콘으로 재시작한다.
