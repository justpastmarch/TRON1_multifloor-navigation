# 지연 후 재출발과 상승 중앙 복귀 수정 · v19

## 확인한 문제

OBSERVED / F1 / Safety S2 · Mobility M4: `ui_test_20261002_004307_0bf70081.bag`에서 약 1.36초의 입력 재관측 후 복귀했지만 전진 명령이 내부 0.0038608부터 증가했다. 기존 `flight_restart_v: 0.55` 분기는 예측 기반 정책에만 적용되고 운영 `observed_feedback` 분기에는 빠져 있었다. 0 명령이 차체를 고정한다는 의미는 아니며, 재출발 중 실제 밀림에 대한 인과 기여는 UNVERIFIED다. S2는 예측 불가능한 재출발 영향, M4는 상승 지속 실패의 우선순위다.

OBSERVED / F2 / Safety S3 · Mobility M4: 같은 BAG에서 좌우 오차가 -12.9cm에서 +26.7cm로 변했고, 최종 추정 yaw는 상승 방향 대비 약 +9.94°였다. 00:43:47 부근 차체의 추정 경계 여유 9.32cm가 anchor 여유 10cm보다 작아 `body/clearance exceeds connected support`가 발생했다. 차체 자체는 설정 영역 안에 있었다. 우측 명령을 송신했지만 경계 접근을 억제하지 못했다. S3는 경계 접근 위험이며 실제 낙상이나 충돌을 관찰했다는 뜻이 아니다.

## 변경한 동작

기존 Supervisor/FSM 안에서 수정했다. 신규 ROS 노드·상태는 없다.

1. 운영 관측 기반 상승도 새 관측으로 입력 회복이 확인되면 전진 입력을 0.55로 복구한다. 같은 epoch, 최신 유효 관측, 관측 차체 지지·자세 검사를 통과해야 한다. 조향은 기존 변화율 제한을 적용하며 전진처럼 순간 복구하지 않는다. 초기 출발의 가속도 제한은 그대로다.
2. 입력 복귀 대기 `flight_input_recover_sec`와 이에 대응하는 `recover_sec`를 2초에서 4초로 변경한다. 대기 중 출력은 0이며 데이터가 없는 상태에서 전진하지 않는다. 관측 warn 0.5초/expire 0.9초, 10초 구간 내 복구 예산 4초는 그대로다. `recover_sec`는 일반 상실 처리의 overdue 표시 시간에도 사용되므로 해당 표시도 4초 기준이 된다.
3. 상승 전용 `flight_centering_lookahead_m: 0.6`, `flight_yaw_kp: 1.0`을 사용한다. 좌우 오차에서 중앙으로 돌아오는 목표 방향을 계산하고 기존 ±10° 이내로 제한한다. 목표 방향보다 이미 충분히 안쪽을 향하면 보정을 줄이거나 반대로 풀어 과도한 회전을 억제한다. 현재 추정 위치·방향을 사용하고 기존 제한된 gyro 감쇠를 더한다.
4. 조향 최대값 0.2, 조향 변화율 0.3, 계단참 속도·회전 방식 및 관측 경계 여유는 변경하지 않는다. 새 파라미터가 없는 경로는 기존 비례 조향을 사용한다. 높이 minimum 판정 및 깊이/적외선 녹화 제외도 유지한다.

이번 조향 목표는 계단 경로에 등록된 중앙선 기준이며, 실시간 양쪽 벽 거리 평균을 새로 추출하는 구현은 아니다. 경로 기준/측위가 실제 계단과 다른 문제는 별도다. 급격한 지연 재발이나 실제 경계 접근이 생겼을 때 무조건 전진시키지 않는다.
