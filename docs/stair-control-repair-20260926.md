## 구현한 동작

1. **조향·전진 후보 공동 선택.** 변화율 제한 안에서 서로 다른 조향 후보를 만들고 전진 최대 입력부터 검사한다. 가능한 후보 중 중앙선으로 접근하는 방향을 선택한다. 전진을 줄일 때도 실제 도달 가능한 속도 구간을 나눠 같은 감속값을 반복하는 문제를 없앴다. 평행한 방향만 유지하면서 옆으로 치우쳐 남지 않도록 중앙으로 향하는 목표 방향을 평가한다.
2. **시간이 지난 측위에 짧은 gyro 회전 보완.** 기존 IMU 콜백을 공유하고, 마지막 LiDAR 자세부터 이미 수신한 IMU까지만 회전을 적분한다. 미래 시각 자료, IMU 간격 누락, 다른 epoch의 데이터는 사용하지 않는다. LiDAR 좌표·타임스탬프는 덮어쓰지 않는다. IMU의 마지막 수신 이후를 임의 외삽하지 않으므로 남은 지연도 진단에 기록한다.
3. **지연 중 추가 가속 금지.** `DEGRADED`에서도 사용할 수 있는 마지막 geometry와 최신 gyro로 명령을 재검사한다. 새 gyro도 없으면 기존 명령을 다시 검사한다. 지연 중 추가 가속과 도착 완료는 허용하지 않으며 기존 만료시간은 그대로다. 매 경고마다 무조건 0으로 끊는 정책으로 바꾸지는 않았다.
4. **좁은 범위의 경계 여유 회복.** 기존 요구 여유 12 cm 중 측위 기준점 불확실성 10 cm는 유지한다. 그 바깥 추가 여유 2 cm만 부족한 경우, 현재와 gyro 보완 방향 양쪽에서 경로가 지지영역 안에 있고 표본 clearance가 감소하지 않으며 예측 끝에 정상 여유로 복귀하는 후보만 허용한다. 표본 사이 보간 오차도 기존 방식으로 검사한다. 실제 경계 밖이거나 10 cm 기준도 충족하지 못하는 자세는 계속 거절한다. **BAG의 7.60 cm 사례를 강제로 통과시키지 않는다.**
5. **두 번째 상승 진입 정렬.** 계단참에 있으면서 중심선·방향이 어긋난 상태에서 두 번째 상승을 시작하면, 같은 기존 phase 안에서 마지막 계단참 waypoint로 저속 접근한 뒤 상승 방향을 맞춘다. 정렬 중 지지영역은 계단참으로 제한한다. 정상 연속 운행에서 이미 정렬됐다면 추가 동작하지 않는다. 정렬 시간도 기존 phase 예산에 포함된다.
6. **실제 송신 및 최초 fault 보존.** WebSocket send가 성공한 프레임의 정규화 XYZ와 시각을 별도로 기록한다. RViz에는 계산 요청과 마지막 실제 송신 및 경과 시간을 구분한다. 성공적으로 0을 송신한 뒤 내부 표시도 0으로 바뀐다. 최초 fault의 실제 사용 관측, 시각, 후보 및 탈락 사유는 후속 `HANDOFF_OVERDUE` 메시지로 덮어쓰지 않는다. TX는 로봇 수신·토크 확인과는 다르다.
7. **검토 중 발견한 기존 정체·정합 검사 보완.** 새 평지 phase의 초기 오차가 유지 hysteresis 두 문턱 사이에 있으면 움직이지도 완료하지도 못하던 문제를 수정했다. 자동 진입점 정합에서 +Z가 뒤집힌 회전도 중력 보존 검사를 통과할 수 있던 누락을 막았다.

정책 버전은 `2026-09-26-candidate-control-v1`이다. 기존 `tracking_status`와 `control_debug`에 표시된다. 설정 파일 해시가 같아도 코드가 갱신됐는지 이 값으로 구분할 수 있다.

- 계단 모드 전진 입력 1과 조향 입력에 대한 실제 이동·회전·응답 지연 및 순간 변화 범위. 예측기는 아직 기존 명령 스케일의 운동 모델을 사용하고, 이를 진단에 `stair response unverified`로 명시한다. 평균 BAG 속도로 예측 범위를 임의 축소하지 않았다.

- 실제 계단 경계·높이와 경로 좌표의 일치. 도착 지점을 앞당겨 실패를 숨기지 않았다.

## 적용과 다음 시작점

원래 저장소의 기존 세 소스 파일과 새 회귀 테스트에 반영한다. 진행 중인 노드를 재시작하거나 로봇을 움직이지 않는다. 따라서 이미 실행 중인 supervisor가 있다면 그 프로세스는 기존 코드를 계속 사용할 수 있다. 다음 시험은 기존 실행 절차로 supervisor를 새로 시작한 뒤 정책 버전이 위 값인지 확인해야 한다.

원래 저장소 루트에서 설정만 검사하는 명령은 다음과 같다. 로봇 명령을 보내거나 ROS 노드를 시작하지 않는다.

```bash
./stair_control_session.sh check
```

새 프로세스 실행 뒤 정책 버전 확인은 기존 진단 토픽을 사용한다.

```bash
rostopic echo -n 1 /stair_supervisor/tracking_status
```

이 문서는 곧바로 전체 계단 주행을 지시하는 명령서가 아니다. 다음 현장 단계는 RC 회수가 가능한 상태에서 계단 모드 조향 응답을 짧게 측정하고, 그 결과를 반영해 첫 상승부터 확인하는 것이다.
