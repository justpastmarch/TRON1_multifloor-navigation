# 계단 주행 후 점검 (`field_check.py`)

주행 BAG를 읽기만 하고 ROS·로봇에는 연결하지 않는다.

```bash
source /opt/ros/noetic/setup.bash
python3 src/stair_supervisor/scripts/field_check.py /mnt/ethan/tron-bags/live/ui-tests/ui_test_<날짜>_<시각>_<id>.bag
# 여러 개, JSON 저장: ... --json out.json BAG1 BAG2
```

`_raw.bag`가 아니라 같은 이름의 본 BAG를 넣는다.

## 항목과 판단

| # | 항목 | 정상 | 이상 신호 |
|---|---|---|---|
| 0 | `config_sha256` | `OK` (로컬 설정과 같음) | `MISMATCH`: 이 브랜치가 배포되지 않음 → 나머지 판단 무의미 |
| 1 | 구간 횡이동 기울기 | 옥상 1구간 0° 근처 (템플릿 회전 `92fa49f`) | 기준처럼 +8~+10° 유지, 또는 반대 부호로 비례 증가 |
| 2 | `entry_attitude_check` | 진입마다 기록, 대부분 `action: none` | 기록 없음, 재정렬 4 s 초과 |
| 3 | 회복 사용 | `flight_basis:heading/steering` 등장 시 정지 없이 이어짐 | 회복 직후 같은 구간 정지 |
| 4 | 회전 | 시간·전진 드리프트·최소 여유를 기준과 비교 (`max_w` A/B) | 최소 여유 감소, 시간 증가 |
| 5 | 첫 정지 원인·TX 간격 | 새 유형의 정지 없음, 주행 중 TX 간격 p99 ≤ 0.1 s | 이번 브랜치 이후 처음 보는 정지 유형 |

회전의 "전진 드리프트"는 회전만 명령한 구간의 몸체 전방 속도다. 로봇 하드웨어 특성으로 생기는 외란이며 결함으로 보지 않는다. 회전 시간은 phase 전체 시간이라 정지·위치 유지 시간을 포함한다.
