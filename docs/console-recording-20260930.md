# UI 주행·테스트·정지

2026-09-30. 기존 mission manager 안의 로컬 UI에 연결했다. ROS 제어 노드는 추가하지 않았다. 테스트 중에는 사용자가 요청한 rosbag 녹화 프로세스가 추가된다.

| 버튼 | 동작 |
|---|---|
| 주행만 시작 | 선택한 목적지로 기존 /mission 주행 요청. UI 녹화 시작 안 함 |
| 테스트 시작 · 녹화 포함 | 경로 확인 → 녹화 준비 → 경로/상태 재확인 → 같은 주행 요청 |
| 정지 · 녹화 저장 | UI 소유 임무 취소 요청과 녹화 SIGINT. 파일 저장은 비동기 완료 |

경로 확인 버튼은 선택 사항이다. 시작 버튼도 서버에서 경로와 준비 상태를 검사한다. 정지 중 새 주행을 보내지 않으며, 녹화 준비 중 정지를 눌렀으면 나중에 주행 명령을 보내지 않는다. 임무의 성공·실패 종료도 UI 녹화를 자동 종료한다. 오래된 콜백이 새 임무의 녹화를 중단하지 않게 실행 세대를 구분한다.

## 녹화

- 위치: `/mnt/ethan/tron-bags/live/ui-tests/ui_test_날짜_시각_고유값.bag`
- 범위: `--all`, 발행 중인 모든 토픽. 카메라·LiDAR·IMU·조이스틱·TF·지도·제어·상태를 포함하되 실제 발행되지 않는 센서 데이터는 만들 수 없다. 이후 생기는 토픽은 rosbag의 검색 주기에 따라 구독된다.
- 분할·시간·파일 크기 제한 옵션 없음. 물리 저장 공간·전송 성능·rosbag 자체 동작까지 무제한이라는 뜻은 아니다.
- 지정 디스크가 마운트되지 않거나 녹화 시작에 실패하면 테스트 주행을 보내지 않는다. 임시로 시스템 디스크에 대신 기록하지 않는다.
- `.active` 파일 생성과 recorder의 현재 발행 토픽 구독 등록을 확인한 뒤 주행을 보낸다. 등록 확인은 모든 메시지가 손실 없이 기록됐다는 보장은 아니다.
- rosbag Python CLI 중간 프로세스가 먼저 종료되는 사례를 격리 시험에서 발견하여, 설치된 native `rosbag/record`를 직접 실행하고 실제 파일 작성 프로세스 종료를 기다리도록 했다.
- 정지 시 SIGKILL로 잘라내지 않는다. UI는 저장 중을 표시하고, 종료 코드 0·최종 .bag 존재·.active 부재를 확인한 후 저장 완료로 표시한다. 저장 지연에 별도 강제 종료 제한을 두지 않았다.
- 오류·비정상 종료 시 파일과 별도 `.log`를 보존한다. 실행 중 녹화가 실패하면 UI에 오류를 표시하며, 그 이유만으로 로봇 주행을 자동 취소하지 않는다.
- UI가 시작하지 않은 녹화는 종료하지 않는다. UI-enabled run.sh는 기존 자동 녹화를 중복 시작하지 않는다. 이전 실행에서 이미 켜진 별도 녹화에는 소급 적용되지 않는다.

## 실행

기존 스택이 종료된 상태에서 저장소 최상위에서 실행한다. 이미 실행 중인 스택과 중복 실행하지 않는다.

```bash
MISSION_CONSOLE_PORT=8765 STAIR_RECORD=0 ./run.sh
```

같은 PC에서 `http://127.0.0.1:8765`를 연다. 브라우저를 여는 것만으로 주행·녹화가 시작되지 않는다. 정지는 기존 상태머신에 취소를 요청하는 동작이며 하드웨어 emergency stop이나 물리적 자세 고정을 의미하지 않는다. 실제 종료 상태와 녹화 저장 완료를 별도로 확인한다.

RF 추가 계단·하강·사진 순회·승인 복귀는 이번 버튼 추가로 구현되는 것이 아니다. 해당 기능은 기존 capability 제한을 유지한다.

UNVERIFIED: 실제 센서 전체 대역폭, 1TB 디스크 실녹화, UI 실주행. 실행 중인 운영 스택은 재시작하지 않았고 로봇 명령을 보내지 않았다. 파일 저장 완료 표시는 데이터 품질 판정과 별개다.

임무 중단/기록 소유권 변경: Safety S2(실기 동작 미검증), Mobility M2(테스트 준비 실패 시 시작 제한), TUNE. 제한은 녹화 포함 테스트 시작에만 적용하며 주행만 모드에는 디스크 준비 조건을 적용하지 않는다. 저장 공간/녹화 문제를 해결한 뒤 다시 시작하거나 주행만 버튼을 사용할 수 있다.
