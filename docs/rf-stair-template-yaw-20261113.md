# 옥상 계단 진입 템플릿 방향 보정 (2026-11-13)

`stair_5f_rf_up_entry.npy`를 진입점 (−0.45, 0) 기준으로 **−6.7°** 회전했다. `stair_lidar_3f_4f_test.yaml`의 sha256만 갱신했고, 경로 다각형·계단 구간 좌표는 바꾸지 않았다.

## 문제

진입 때 LiDAR 점군을 이 템플릿에 정합한다. 템플릿 속 계단과 벽은 경로 좌표에서 +6.7° 방향인데, 같은 좌표로 정의된 옥상 경로(1·2·3구간, 지지영역)는 계단을 0° 방향으로 가정했다. 그래서 로봇은 실제 계단을 따라 오르는데, 제어기에는 1구간 끝에서 약 +0.32 m 치우친 것으로 보였다.

## 근거

| 측정 | 결과 |
|---|---|
| 현장 점군 105회 (챌판·벽 두 방법, 9/30–11/06) | 계단 방향 +6.5° / +6.8° (중앙값), 편차 ±1° |
| 템플릿 자체 | 챌판 +7.0°, 벽 +6.5° |
| 2·3구간 현장 점군 | 1구간과 같은 각도 |
| 상승 1구간 횡이동 (27회) | 진행 거리에 비례(R² 중앙값 0.78), 기울기 중앙값 +8.3° |
| 3F→4F (같은 방법) | 기울기 약 0°, 비례성 없음 |
| 보정 좌표의 계단참 벽 | 먼 쪽 벽 x=3.53 m, 왼쪽 벽 y=−0.67 m. 다각형(3.45, −0.615)은 벽보다 5–8 cm 안쪽 |

보정 좌표로 다시 계산한 옥상 정지 지점의 지지 여유:

| 정지 | 현재 좌표 | 보정 좌표 |
|---|---|---|
| 10/30 1구간 | 0.009 m | 0.285 m |
| 10/16 11:00 1구간 | 0.040 m | 0.200 m |
| 10/16 09:03 3구간 | 지지영역 밖 | 0.176 m |
| 10/16 08:19 계단참 회전 | 0.029 m | 지지영역 밖 (실제 벽에서 1.5 cm) |

## 검증

- 보정 템플릿의 계단 방향: 챌판 0.0°, 벽 +1.0°.
- 생산 정합 함수(`fit_entry_template`)로 기록 진입 재현: 승인된 회차에서 계단이 0°±1°로 놓이고 로봇 방향이 −6.7° 바뀜. 같은 입력에서 정합 품질은 같거나 약간 좋음(RMSE −0~0.003 m). 재현 입력은 표시용 점군이라 다수 회차가 두 템플릿 모두에서 거부됨(실제 진입의 고밀도 로컬 지도와 다름).
- `validate_bundle --validate-production-config`, `run.sh --check`, `stair_supervisor` 테스트 539개 변화 없음.

## 남은 것

- 회차마다 ±1.5–3° 더 흔들리는 정합 편차(예: 11/06 회차 약 +9.5°)는 이 보정과 별개다.
- 옥상 하강(`stair_5f_rf_down`)은 지도 위치로 진입하므로 영향이 없다. 3F↔4F, 4F↔5F도 영향이 없다.
