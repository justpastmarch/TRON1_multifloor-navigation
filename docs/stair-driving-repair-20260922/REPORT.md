# 계단 주행 복구 구현 결과

2026-09-22 작업 기준. **시작 명령·경계 검사·연결 시험·실행 진단을 구현했다. 공통 3→4층 경로의 실측 좌표와 실제 자동 완주는 미완료다.** 기존 BAG를 같은 가정 경로로 평가하면 기존 중단이 그대로 남는다. 이번 소프트웨어 검증을 계단 주행 성공으로 표현하지 않는다.

OBSERVED는 코드·파일·이번 오프라인 실행에서 직접 확인한 내용, INFERRED는 정합 자료를 바탕으로 한 해석, UNVERIFIED는 실측·실기 확인이 필요한 내용이다. S/M 0~4는 잠재 안전/주행 영향이며 사고 발생이나 성공률을 뜻하지 않는다.

## 같은 BAG에서 남은 문제

원본 BAG에서 추출한 기존의 승인된 LiDAR pose를 이번 정책에 순서대로 입력했다. 계산한 명령은 기록 로봇에 영향을 주지 않으므로 이는 닫힌 루프 주행 시험이 아니다. 비교 대상은 직전 오프라인 후보의 동일한 가정 경로와 시작 변환이다.

| BAG | 이전 중단 | 이번 중단 | 이번 진단으로 분리한 이유 |
|---|---|---|---|
| 102101 | 13.7993초 SUPPORT_LIMIT | 동일 | 현재 외곽 여유 12.786cm, 적용 마진 12cm. 예측 이동에서 벗어남. 높이 목표 오차 58.315cm, 진행·다음 영역 조건 미충족 |
| 105713 | 22.7998초 SUPPORT_LIMIT | 동일 | yaw 90.268°인데 첫 구간. 높이는 허용되지만 진행·계단참 전체 진입 조건이 미충족. 현재 여유 20.126cm, 예측 이동에서 벗어남 |
| 103313 | 1.2000초 CORRIDOR_LIMIT | 동일 | 실제 투영 외곽은 구역 안이지만 여유 11.823cm가 마진 12cm보다 1.772mm 작음. 시작 정합 오차를 모르는 상태에서 이것을 물리 충돌로 해석할 수 없음 |

**OBSERVED · S2 / M3:** 이번 코드 수정만으로 위 중단은 개선되지 않았다. [전체 정책 결과](evidence/recorded-control-results.json)에 좌표·명령·조건을 저장했다. 103313의 수치를 근거로 마진을 2mm만 줄여 통과시키지 않았다. 해당 수치는 가정한 시작 좌표에서 계산한 값이다.

**INFERRED · S2 / M3:** 두 기준 BAG의 첫 몸체 좌표는 같은 물리 출발점이 아니다. 수평면 후보에서 계단참 전면 X의 1% 분위수는 각 첫 몸체 좌표계 기준 약 2.812m/2.557m다. 계단참 표면 Z 중앙값도 약 0.793m/0.736m다. 이는 부분 점군의 경계 후보이며 실측 경계의 정밀도 수치가 아니다. 첫 단 앞 바닥이 가려져 있어 공통 첫 단 기준 시작 변환을 확정하지 못했다. 몸체 목표 Z를 바닥 표면 Z와 혼용하면 안 된다.

[계단참 후보 수치](evidence/landing-measurements.json) · [원본 점군 누적](evidence/raw-geometry-overview.png) · [수평면 분포](evidence/horizontal-surfaces.png)

전체 점군 간 정합은 같은 LiDAR와 추정 궤적에 의존한다. 그것으로 독립 위치 정확도나 실제 주행 성능을 증명하지 않는다. 전역 정합의 작은 roll/pitch 차이를 실시간 좌표 보정으로 넣지 않았다.

|---|---|---|---|
| 연결된 영역 검사 NARROW | 계단 외곽/빈 공간으로 명령. 사용자가 제공한 계단 폭과 점군에서 외곽 존재 확인 | 해당 구간의 실제 인접 영역만 합침. 꼭짓점만 검사하면 내부 틈 반례 실패. 수평 기하로만 검증 | 시작 좌표·실제 외곽 재확인 후 새 시험. S2/M3 |

| roll/pitch envelope UNVERIFIED | 기체 기울어짐·접촉 불안정 | 기존 후보 범위. 몸체 projection은 실제 무게중심/접촉 모델이 아님 | RC로 자세 회수, 측위/자세 재확인. S3/M2 |

계단 중간부터 시작하는 모드 ACK에는 기존 보정 경로가 남는다. ACK 전 기체가 해당 명령을 어느 모드로 실행하는지와 실제 자세 유지 성능은 UNVERIFIED다. `handoff_sec + max_duration_sec`는 설정된 소프트웨어 시간 예산의 합이며 정지 명령 전달 시간까지 보장하는 물리 상한이 아니다.

## 적용과 남은 작업

실제 저장소의 수정 파일만 해시를 대조해 반영한다. 변경 전 사본·변경 목록·복구 도구는 [작업 기록](/home/m3tron/.codex/.chatgpt-projects/g-p-6aa37f17097c81919ca6c59ce41e856c/stair-driving-repair-implementation-20260922)에 보존한다. 최종 적용 파일·추적 동결 해시·Git 비교는 같은 폴더의 `deployment.json`에 기록한다. 이 작업은 전체 repository 재감사가 아니다.

**안전 verdict:** 코드의 시작/취소/경계 반례를 수정하고 오프라인 시험에서 확인했다. 실제 자세 유지·통신 응답·RC 회수 동작은 UNVERIFIED.

**Mobility verdict:** 잘못된 내부 경계와 완료 후 옛 명령 차단을 제거했지만, 기존 BAG의 가정 경로 중단은 그대로다. 공통 경로 정합과 실제 전체 주행은 미완료.

**2026-09-23 정정 · OBSERVED:** 사용자는 이미 3→4층 단수·단 치수를 제공했다. 2026-08-21 원문은 9단→계단참→10단, 2026-09-04 원문은 계단 폭 1.23m·단 깊이 0.28m·단 높이 0.17m, 계단참 가로 2.70m·깊이 1.48m다. 2026-09-11에도 3→4층과 4→5층의 9+10단 구성을 다시 확인했다. 원문과 이를 저장한 기존 site 설정을 [복구한 치수·출처](evidence/recovered-site.json)에 연결했다. 치수 응답 대기라는 이전 판정은 조사 누락이므로 철회한다. 사용자에게 재입력을 요구하지 않는다.

단수×단 높이로 계산한 상승량은 첫 구간 1.53m, 두 번째 1.70m, 합계 3.23m다. 이는 제공값의 계산이며 새 실측 결과가 아니다. 남은 일은 이 형상을 BAG의 출발 위치/방향 및 몸체 기준 좌표와 연결하는 것이다. 기존 녹색 추적을 그대로 사용하며 경로 기준으로 재정합한다. 단수×깊이를 몸체의 명령 이동거리로 곧바로 넣거나, 실기 검증 없이 commissioned를 활성화하지 않는다.

복구 후 실제로 진행한 [동일 형상·BAG별 원점 재평가](GEOMETRY_RECOVERY.md)에서는 105713이 19.60초에 첫 구간에서 LANDING으로 넘어갔지만 19.80초에 마진 검사로 중단했다. 102101도 13.60초 예측 경계 중단이 남았다. 이는 불완전 관측에서 얻은 오프라인 정합 후보의 결과이며 전체 주행 개선으로 판정하지 않는다.

같은 원문에는 계단에서 WebSocket 기준 전진 명령이 최소 0.5는 돼야 한다는 관찰도 있다. 이는 물리적 최소 속도(m/s)와 동일한 숫자가 아니다. 기존 낮은 속도 후보와 명령 정규화 경로의 정합을 후속 제어 검토에 포함하며 이번 원문 복구에서 임의로 속도를 올리지는 않았다. 첫 단 경계와 진입 몸체 위치를 공통 좌표에 놓은 뒤 같은 route를 두 BAG에 적용하고 짧은 실기→연결 시험→정상 임무→NAV/층 전환 순서로 검증한다.

실행 도구와 RViz 사용 방법은 [최신 적용 안내](../tron-documentation-20260922/APPLICATION_GUIDE.md)에 있다. 이 차례에서 TRON·미니PC 연결, 생산 프로세스 재시작, 실제 이동은 수행하지 않았다.
