# 3→4층 계단 주행 복구 계획

2026년 9월 22일 · 계획 보고 · 운영 코드 변경 및 로봇 실행 전

<span id="section-1"></span>

## 1\. 목표와 작업 순서

**개선된 LiDAR 추적을 유지하면서, 계단 진입점부터 4층 도착까지 기존 Stair Supervisor가 정상적으로 구간을 전환하고 주행하도록 만든다.** 이 경로가 검증되면 기존 3층 NAV와 연결해 ‘임의 시작 위치 → 계단 진입점 → 4층 도착’을 확인한다.

작업 순서는 **시작 명령 버그 수정 → 계단 좌표 정합 → 경계 통과와 상태 전환 검증·수정 → 실행 설정 통합 → 짧은 실기 보정 → 전체 주행**이다. 시작 명령 수정과 점군 분석은 서로 독립적으로 진행할 수 있다. 실기 적용은 검증된 수정본과 해당 경로 설정을 함께 사용한다.

새 ROS 노드·명령 송신자·SLAM은 추가하지 않는다. 기존 mission manager, floor manager, move\_base, Stair Supervisor의 역할을 유지한다. 추적 코어, IMU 보정, 기존 녹색 궤적은 동결한다. 구조 변경이 필요한 사실이 나오면 변경 이유와 대안을 먼저 보고한다.

완료 기준은 BAG 그림이 좋아지는 것이 아니라 **실제 명령에 반응하는 로봇이 진입·상승·계단참 이동·회전·재상승·도착을 수행하고, 종료 상태와 층 전환이 일치하는 것**이다. 이번 문서는 계획이며 이 결과를 이미 달성했다는 뜻은 아니다.

## 3\. 1단계: 시험 시작 명령부터 바로잡는다

**수정 위치:** 기존 `supervisor.py`, `stair_feedback.py`와 관련 시험.

  - 평지 진입점에서 시작하는 첫 구간 시험에 한해, STAIR 모드 응답을 기다리는 동안 명령을 0으로 유지한다.
  - 모드 응답 완료 시 제어기의 이전 명령·시간 이력을 실제 보낸 0 명령에 맞춘다. 그 뒤 첫 구간 시험 시간을 시작한다.
  - 응답 실패·취소·통신 예외의 기존 상태와 소유권 처리를 유지한다. 시험 종료를 계단 도착이나 층 이동 성공으로 보고하지 않는다.
  - 별도 후보 패치를 그대로 덮어쓰지 않고 현재 변경 사항과 비교해 필요한 부분을 적용한다.

**제한 범위:** 이 수정은 첫 구간 시험의 시작 시점을 명확히 하는 것이다. 계단 중간의 자세 유지·종료 모드 전환까지 일괄적으로 0 명령으로 바꾸지 않는다. 현재 후보의 `neutral_only` 적용 범위도 함께 확인한다.

**검증:** 응답 대기 전체 구간의 전송 명령이 0인지, 응답 후 첫 명령이 정해진 가속 한계에서 시작하는지, 시험 타이머가 응답 전 시간을 포함하지 않는지 확인한다. 정상 응답·지연·실패·취소·재시험을 포함한다. 0 명령 시험 통과를 물리적 정지 유지 검증으로 해석하지 않는다.

**완료 산출물:** 작은 패치, 회귀 시험 결과, 모드 요청→응답→첫 비영 명령의 시간표.

## 4\. 2단계: 실제 계단과 로봇 시작 위치를 같은 좌표에 놓는다

### 좌표 기준

계단 경로의 물리 기준은 첫 단 앞 경계의 중앙과 첫 계단 진행 방향으로 정한다. 수직축은 보존한 중력 방향을 사용한다. 기존 추적의 로컬 좌표계는 유지하고, 경로와 로컬 좌표 사이 변환만 계산한다. 각 BAG의 첫 프레임을 같은 물리 위치라고 가정하지 않는다.

바닥·계단참의 표면 높이, LiDAR 높이, 제어에 쓰는 몸체 기준점 높이를 구분한다. 기존 `flight_1/2`의 Z는 몸체 경로 기준이므로, 바닥 높이를 그대로 넣지 않는다. 이미 확인한 센서 장착값과 해당 시점 자세를 적용한다.

### 분석 절차

1.  102101·105713의 원본 점군과 동결한 추적 결과를 사용한다. 103313은 반례·회귀용으로 함께 확인한다.
2.  진입·계단 직선·계단참·상부 평지의 여러 시점에서 점군을 모으고, 높이·방향·연결 관계를 함께 보며 첫 단, 계단 끝, 계단참 외곽, 다음 계단 방향을 추출한다. 가장 큰 평면 하나를 바닥이라고 간주하지 않는다.
3.  알려진 폭 1.23m, 계단참 가로 2.70m·깊이 1.48m, 기체 0.45×0.45m, 센서 XY 중앙·높이 0.18m·pitch +5°를 교차 확인 자료로 사용한다. 점군을 이 치수에 억지로 맞추지 않는다.
4.  각 BAG의 시작 위치·방향을 공통 계단 기준에 정합한다. 경계 검출 오차, 좌표 정합 오차, 관측 불가 부분을 따로 기록한다.
5.  한 BAG로 만든 경계·경로를 동결하고 다른 BAG에 적용한다. BAG별로 경로를 늘리거나 줄여 통과시키지 않는다. 시작 자세 변환은 기록마다 달라도 물리 계단 형상은 동일해야 한다.

**정합 결과를 RViz에 겹쳐 보여 줄 항목:** 원본 점군, 기존 녹색 추적, 45cm 기체 외곽, 첫 단·계단참·상부 경계, 현재 목표, 현재 단계. 과거 수동 FINAL\_ARRIVAL 표식은 정답이나 제어 입력에 쓰지 않는다.

**완료 조건:** 두 기준 BAG에서 동일한 계단 경계가 일관되게 설명되고, 기존 첫 구간 중단을 일으킨 조건을 항목별로 설명할 수 있어야 한다. 같은 LiDAR로 만든 지도와 궤적의 일치는 기하 정합 증거이며 독립 위치 정확도 증명은 아니다. 점군에 경계가 안 보이거나 후보가 여러 개이면 그 항목만 현장 사진·거리 확인 대상으로 남긴다.

**산출물:** 공통 3→4층 경로 후보, BAG별 시작 변환, 경계·오차 근거표, RViz 비교 자료. 숫자를 확정할 근거가 부족하면 후보 상태를 유지한다.

## 5\. 3단계: 경계 통과와 상태 전환을 일치시킨다

**핵심 수정 위치:** 기존 `stair_feedback.py`. 필요할 때만 `supervisor.py`의 전환 순서를 소폭 수정한다. 공개 phase 이름과 action 인터페이스는 유지한다.

### A. 실제 계단참 진입을 완료 조건과 연결

첫 구간 종료는 ‘기존에 정한 임의 거리까지 직진’과 ‘계단참에 들어왔음’이 충돌하지 않도록 정리한다. 현재 진행·높이 변화·기체 외곽의 다음 구역 진입 조건을 새 경계에 맞춰 일관되게 만든다. 회전 시작점까지의 이동은 기존 계단참/회전 경로에서 담당하게 해, 첫 계단 종료점과 회전 경유점을 혼동하지 않는다.

상부 도착도 새 경계와 기체 기준으로 확인한다. 마지막 단이 남았는데 높이 하나만 맞았다는 이유로 완료하거나, 지정 시간이 지났다는 이유로 도착 처리하지 않는다.

완료 조건은 아래처럼 단계별로 명시한다. 표의 필수 항목은 AND로 결합하며, 위치·높이·각도 허용오차는 2단계의 정합 오차와 실측 응답을 근거로 정한다. 이 계획에서 임의의 새 허용오차를 확정하지 않는다.

| 단계         | 필수 완료 근거                                                       | 대기 조건                                     |
| ---------- | -------------------------------------------------------------- | ----------------------------------------- |
| 진입·정렬      | 해당 진입 구역 안의 기체, 시작 목표 위치·방향 범위 충족, 신선한 관측                      | 기존 정착 조건을 적용하고 실기에서 과도 여부 조정              |
| 첫 계단 종료    | 실제 진행·높이 상승 이력, 계단참의 몸체 높이 범위, 기체 전체의 계단참 진입, 해당 단계 시작 이후 새 관측 | 정해진 시간의 추가 정지를 새로 넣지 않음                   |
| 계단참 진입     | 계단참 내부 기체 확인, 같은 좌표 epoch                                      | 다음 회전 경로로 연결                              |
| 회전 경로      | 각 경유점의 위치·목표 방향 조건, 최종 경유점에서 실제 다음 계단 방향 확인                    | 현재 경유점 정착 조건을 기준으로 시험하며 불필요한 반복 대기를 별도 계측 |
| 두 번째 계단 종료 | 두 번째 진행·상승 이력, 상부 몸체 높이 범위, 기체 전체의 상부 구역 진입, 새 관측              | 도착 확인 단계로 연결                              |
| 최종 도착      | 두 구간 진행 이력, 상부 구역·목표 위치/방향 충족, 서로 다른 관측에서 위치·속도·방향 정착          | 기존 정착 확인 후 종료 모드 전환·소유권 전달                |

거리 기준은 새 경계에서 몸체가 실제로 진출하는 위치와 일치시키고, 회전 경유점까지 더 직진하라는 중복 조건으로 남기지 않는다. 계단참 진입만으로 최종 도착이나 층 전환을 선언하지 않는다.

### B. 두 구역을 걸치는 정상 통과 처리

기체가 계단 끝과 계단참에 걸쳐 있는 동안 어느 구역으로 검사해야 하는지 명확히 한다. 현재 구역 하나만 검사해서 정상 통과를 막는 것이 재현되면, 해당 전환 구간에서만 실제로 연결된 이전·다음 영역을 함께 고려한다.

현재 다각형 검사는 볼록 영역을 전제한다. 연결 영역을 처리할 때 중간 빈 공간까지 채우는 볼록 껍질로 넓히거나 네 꼭짓점만 보고 기체 전체가 허용됐다고 처리하지 않는다. 실제 연결 영역에 기체 외곽과 예측 경로가 포함되는지 검사한다. 이 확장이 필요 없다면 기존 단일 영역 검사를 유지한다.

이는 수평 투영의 기하 검사다. 실제 접촉 하중·무게중심·전도 한계를 증명하는 모델로 표현하지 않는다.

### C. 완료 후 이전 단계 명령으로 다시 차단되는지 분리

완료 조건을 만족한 시점에도 이전 직진 명령의 예측 경계 검사가 fault를 만들 수 있는지 회귀 시험으로 확인한다. 재현되면 현재 기체 위치와 다음 구역 진입 근거를 확인한 뒤 기존 소유권 안에서 다음 단계로 전환하도록 정리한다. 실제 송신하는 새 명령은 해당 단계의 경계 검사를 거친다.

구간 완료를 이유로 기하·관측 유효성 검사를 전부 건너뛰지 않는다. 반대로 더 이상 보내지 않을 이전 단계 명령 때문에 유효한 전환을 막는 것도 피한다.

### D. 불필요한 제약의 원인을 분해

한 번에 설정 전체를 바꾸지 않고, 같은 입력에 아래 항목을 따로 적용해 어떤 항목이 막았는지 기록한다.

  - 실제 45cm 외곽의 구역 포함 여부.
  - 경계 정합과 시작 위치의 불확실도.
  - 추가 경계 마진.
  - 명령·회전·관측 나이에 따른 예측 이동.
  - 현재 단계 선택과 완료 조건.

현재 후보의 추가 마진 2cm, 진입 불확실도 10cm, 예측시간 0.9초는 검토 대상이다. 무엇이 과한지 확인하기 전에 일괄 축소하지 않는다. 관측 만료시간과 예측시간을 분리할 필요가 입증되면 해당 경로 설정에만 명시하고, 실제 갱신·통신·명령 반응으로 근거를 정한다.

**완료 조건:** 정상 연결 구간과 잘못된 경계 통과를 구별하는 시험 통과, 각 기존 중단 사건의 원인 설명, 동일 형상의 여러 시작 자세·회전 자세 시험 통과. 수동 BAG 궤적이 후보 회전 경유점을 정확히 따르지 않으면 이를 제어 실패로 집계하지 않는다. 기록 평가는 상태·명령 판단의 타당성을, 명령에 반응하는 모델 시험은 제어 로직을 확인한다. 물리적 성공은 실기에서 확인한다.

## 6\. 제약을 최소 범위로 유지하는 기준

| 조건             | 계획상 처리                       | 불필요한 차단을 줄이는 방법                |
| -------------- | ---------------------------- | ------------------------------ |
| 시작 위치·경로 불일치   | 경로별 재정합                      | 기존 평지 NAV 전체를 차단하지 않음          |
| 작은 횡방향·방향 오차   | 연속적인 보정과 deadband 조정         | 정상 잡음마다 fault/재승인을 요구하지 않음     |
| 짧은 관측 지연       | 기존 유효기간 안에서 제한된 제어, 단계 완료 유보 | 매 프레임 완벽한 정합을 출발 조건으로 추가하지 않음  |
| epoch 변경·측위 단절 | 좌표 유효성에 따라 해당 계단 제어 대응       | 되살아난 센서만으로 취소된 동작을 자동 재시작하지 않음 |
| 구역 경계          | 실제 연결 구역·외곽·오차로 검사           | 임의로 큰 공통 마진을 모든 구간에 적용하지 않음    |
| 첫 구간 4초 시험     | 최초 구동 반응을 확인하는 시험 범위         | 정상 임무에도 4초마다 정지하도록 적용하지 않음     |
| 도착 후 밀림        | 고정 목표·기존 위치 보정의 실기 검증        | 0 명령을 위치 유지로 간주하지 않음           |

관측 상태별 명령·재개 동작도 고정한다. 아래 시간은 현재 후보 기준이며 새 실측 근거 없이 확대하지 않는다.

| 관측/실행 상태                          | 명령과 단계 처리                                                 | 재개 조건                                             |
| --------------------------------- | --------------------------------------------------------- | ------------------------------------------------- |
| 신선한 유효 관측                         | 현재 측정값으로 제한된 보정 명령 계산, 완료 조건 평가                           | 계속 수행                                             |
| 정합 일시 거절 또는 0.5\~0.9초 미만 지연       | 기존 상한을 적용한 마지막 명령 유지, 단계 완료 보류. 새 위치를 추측해서 만들지 않음         | 같은 epoch의 신선한 유효 관측이 돌아오면 정상 평가로 자동 복귀            |
| 0.9초 이상 관측 만료·epoch 불일치·worker 실패 | 현재의 0 명령 전송/STAIR 소유권 유지 경로, 사용자 RC 회수. 연결 단절이면 0 전달도 미확인 | 센서 회복만으로 움직이지 않음. 물리 상태와 현재 위치 확인 후 명시적 시험/임무 재시작 |
| 전송 연결 단절                          | 기존 FAULT·세션 정리 경로. 새로운 0 명령의 도달을 보증하지 않음                  | 연결과 로봇 상태를 확인한 뒤 명시적 재시작                          |
| 취소 또는 시스템에 확인된 사용자 제어권 회수         | 자동 주행 재개 금지, 기존 취소·인계 상태 처리                               | 새 사용자 명령과 유효한 시작 조건                               |

RC만 조작했을 때 그 회수 사실이 현재 로봇 피드백으로 Supervisor에 전달되는지는 실기에서 확인한다. 전달되지 않는다면 기존 취소 요청도 함께 사용해 이전 자동 명령을 종료한다. RC를 놓는 순간 이전 자동 동작이 되살아나는지 반드시 시험한다.

0 명령은 자세 유지 수단으로 보증하지 않는다. 반복되는 짧은 지연에 대해서도 마지막 유효 관측의 실제 나이를 계속 계산하므로, 오래된 명령을 무기한 유지하는 구조로 바꾸지 않는다.

현 단계에서 최소성 증명이 끝난 물리 제약이라고 KEEP 판정을 새로 내리지 않는다. 경계는 NARROW/UNVERIFIED, 마진·지연·제어 이득은 TUNE이다. 구현 결과의 constraint ledger에는 각 제약이 막는 실제 hazard, 근거, 적용 구간, 더 좁은 대안의 검토, 오탐 시 회복 경로를 기록한다. 증명할 수 없는 제약을 KEEP으로 승격하지 않는다.

<span id="section-7"></span>

## 7\. 4단계: 검증본과 실행 설정을 연결한다

**적용 단위는 검증된 코드 + 3→4층 경로 + 실행 모드 설정이다.**

  - 기존 `STAIR_LIDAR_MODE`, `STAIR_LIDAR_CONFIG`, `STAIR_LIDAR_OBSERVE_ONLY` 경로를 사용한다. 전역 기본값을 바꾸어 모든 실행에서 무조건 계단 제어가 켜지게 하지 않는다.
  - 사용할 실행 설정 한 곳에서 3→4층 제어 모드와 경로 파일을 지정하고 실제 로딩 경로를 확인한다.
  - 기존 진단 출력에 설정 절대경로·파일 해시, 모드, route ID, 검증 상태, 시작 좌표 근거를 표시한다. 실행 프로세스가 이 값을 읽었는지 확인한다.
  - `configured`는 로딩 준비, `commissioned`는 경로 실기 검증 상태로 구분한다. 정상 전체 주행 활성화를 위해 증거 없이 flag만 true로 바꾸지 않는다. 초기 실기 시험은 기존 명시적 phase\_test 경로를 사용한다.
  - 기존 RViz 진단에 현재 단계, 경계까지의 최소 여유, 적용 마진, 마지막 유효 관측 나이, 명령 v/w, 완료되지 않은 조건을 표시한다. 새 노드를 만들지 않는다.
  - 시작/종료·실패마다 실행 설정과 센서·제어·상태를 함께 기록하는 기존 시험 실행 절차를 정리해, 매번 별도 BAG 명령을 빠뜨리는 문제를 줄인다. 카메라 실시간 스트리밍은 전제하지 않는다.

### 실기 시험을 위한 허용 범위

현재 오프라인 후보는 미검증 경로의 첫 구간을 최대 4초만 허용한다. 운영 코드의 일반 phase\_test에는 30초 상한도 있다. 이 조건을 그대로 두면 ‘다음 단계 실험으로 확장’이라는 계획을 실행할 수 없다. **기존 phase\_test에 경로별·단계별 시험 예산을 연결하는 작은 수정**을 포함한다.

경로 설정에 선택 항목 `phase_test_limits`를 두어 시험 가능한 기존 phase와 최대 시간을 명시하고, 엄격한 설정 검사에 포함한다. 누락 시 최초 첫 구간 4초만 허용한다. 요청자는 설정된 예산을 초과할 수 없다. 30초라는 공통 상한 대신 해당 phase의 명시된 예산과 기존 profile 전체 timeout을 적용한다. 예산은 경로 길이·회전량·실측 속도·정착 소요시간으로 정하며, 정상 동작보다 짧은 시간으로 강제 실패시키지 않는다.

| 상태                         | 허용할 실행                     | 근거                                                 |
| -------------------------- | -------------------------- | -------------------------------------------------- |
| 경로 준비 전                    | 관찰·오프라인 분석                 | 기본 configured=false                                |
| 경계/시작 정합·시작 버그 검증 완료       | 진입 평지의 첫 구간 4초 phase\_test | configured=true, commissioned=false, 해당 시험 예산      |
| 첫 구동 응답 확인 및 다음 구간 경계 검증   | 지정한 phase만 제한된 실기 시험       | 같은 configured 상태에서 phase\_test\_limits의 검증된 항목만 확대 |
| 각 구간 주행·회전·종료 인계의 실기 확인 완료 | 진입점부터 정상 전체 계단 임무          | 결과를 근거로 해당 3→4 UP 경로만 commissioned=true            |
| 전체 계단 임무 확인 완료             | 기존 3층 NAV부터 연결 시험          | 계단 도착 결과와 층/맵/알림 연결 확인                             |

**연결 시험의 실행 경로도 명시한다.** 기존 phase\_test에 선택적인 `from_entry: true`를 추가한다. 기본값 false는 기존 단일 phase 시험의 의미를 유지한다. true일 때 기존 `phase` 필드는 마지막으로 확인할 단계를 뜻하며, 진입 확인부터 그 단계까지 기존 순서의 연속 구간만 실행한다. 임의 순서나 단계 건너뛰기는 허용하지 않는다. 같은 Supervisor·좌표 epoch·진입 근거·명령 소유권을 유지하므로 중간마다 시작 위치를 새로 가정하지 않는다.

연결할 모든 단계에 설정된 시험 예산이 있어야 하며, 단계별 제한과 요청한 전체 `max_duration_sec`를 함께 적용한다. 전체 시간은 허용 단계 예산 합과 기존 profile timeout도 넘을 수 없다. 모드 응답 대기는 기존 handoff 제한으로 별도 관리한다. 단계 타이머는 응답 완료 후 시작하며, 이후 각 단계 전환 시 단계 타이머만 갱신한다. 연결 시험은 정상 임무와 같은 전환 로직을 사용하고 종료 처리만 구분한다.

허용 목록을 최종 도착 확인까지 확대하면, 두 구간 이력을 이어서 최종 조건을 검사할 수 있다. 이때도 **정상 성공 반환·floor/map 변경·자동 다음 미션은 발생시키지 않는다.** 목표 단계 도달을 진단으로 기록하고 기존 시험 종료/RC 인계 경로를 사용한다. 명시적 물리 인계 절차로 종료 모드 응답을 확인한다. 이후 근거를 갖춘 경로만 정상 임무에 활성화한다. 기존 action 정의나 공개 phase 이름은 바꾸지 않고, 시험 요청 파싱과 검증만 확장한다.

중간 phase 시험에는 그 phase의 실제 시작 위치·방향·구역 조건이 필요하다. 첫 진입점 자세를 계단참의 현재 자세처럼 재사용하지 않는다. 같은 연속 시험에서 좌표 변환을 재사용할 때도 epoch·유효 관측·실제 시작 상태를 확인하고, 과거 측정의 시각만 새로 붙이지 않는다. 이 증거를 확보하지 못하면 진입점부터 연결해서 해당 단계까지 시험한다.

이번에는 미니PC나 TRON에 접속하지 않았으므로 현재 실행 상태는 추정하지 않는다. 실제 배포 시 대상 호스트·워크스페이스·프로세스의 설정을 먼저 확인한다. 현재 worktree의 다른 수정은 보존하고 이번 변경 파일만 차이·해시로 추적한다. 되돌릴 때도 이번 패치와 이번에 만든 실행 설정만 대상으로 한다.

<span id="section-8"></span>

## 8\. 5단계: 실기에서 보정 방향과 크기를 맞춘다

실기 시험은 사용자가 확인한 조종기 제어권 회수·자세 유지 절차를 사용한다. 이 계획에 emergency-stop API 호출이나 별도 비상정지 장치 요구를 추가하지 않는다. 제어권 회수는 사용자의 기존 운용 조건이며, 소프트웨어가 전달한 0 명령은 물리적 자세 유지와 별도로 확인한다.

| 순서 | 시험                     | 측정할 것                                      | 다음 시험으로 넘어갈 근거                         |
| -- | ---------------------- | ------------------------------------------ | -------------------------------------- |
| 1  | 진입 평지에서 모드 전환과 짧은 첫 구간 | 응답 시각, 실제 첫 움직임, 명령/관측 방향, 취소·RC 회수        | 예상 전 움직임 없음, 보정 부호 일치, 개입 후 상태 일치      |
| 2  | 첫 계단 구간                | 중심·방향 오차, 전진 응답·미끄러짐, 명령 포화                | 보정이 오차를 줄이고 정상 진입이 경계로 오차단되지 않음        |
| 3  | 계단참 진입·이동·회전           | 단계 전환 위치, 외곽 여유, 다음 계단 방향, 반복 회전 여부        | 실제 공간 안에서 다음 계단에 정렬되고 불필요한 멈춤 없음       |
| 4  | 두 번째 계단·상부 도착          | 마지막 단 통과, 기체 진출, 도착 판정, 밀림 복구              | 물리적 도착과 상태 완료가 일치, 위치 유지 응답 확인         |
| 5  | 3층 NAV부터 전체 연결         | 명령 소유권, 계단 진입 anchor, 도착 후 floor/map·UI 상태 | 실제 4층 도착 전 성공/층 전환 없음, 완료 후 상태·맵·알림 일치 |

보정 이득은 횡방향·방향·전진 응답을 나눠 작은 시험으로 조정한다. 한쪽으로 밀리는 경우 실제 외부 이동과 추정 변화가 같은지 영상·현장 기준으로 확인한다. 관측 좌표가 틀린 문제를 큰 회전 이득으로 덮지 않는다.

첫 4초 시험은 기존 후보의 초도 시험 범위로만 사용한다. 응답을 확인하면 단계별 시험으로 확장하고, 전체 임무에서 일정 시간마다 중단하는 규칙으로 남기지 않는다. 시험 중간에 사람이 회수한 시행은 성공에서 제외하고 원인을 기록한다.

도착 대기는 현재 계단 종료 보정과 기존 NAV 위치 복귀의 책임을 확인한다. 새 명령이 들어오면 이전 대기 보정이 다음 명령과 경쟁하지 않게 기존 소유권·취소 처리를 검증한다. v/w 명령으로 확인할 수 없는 roll/pitch 균형이나 접지 문제는 코드만으로 해결했다고 보고하지 않는다.

## 9\. 필수 회귀 검증

기존 관련 시험에 아래 사례를 추가한다. 계획상의 목표이며 이번에 새로 실행한 결과는 아니다.

1.  동결 추적 결과의 sensor 시각·수락 상태·좌표가 기존 수치 허용범위 내에서 보존됨.
2.  모드 응답 전 0 명령, 응답 뒤 이력 초기화, 타이머 시작, 실패·취소·재시험.
3.  같은 물리 경로를 서로 다른 기록 시작 위치·방향에 적용.
4.  계단과 계단참에 기체가 걸친 정상 전환, 실제 빈 공간을 포함한 잘못된 전환.
5.  현재 구간 완료 후 이전 명령의 예측 검사 때문에 생기는 false fault와 실제 다음 명령 경계 위반을 구분.
6.  150° 방향에서 180° 목표 회전 완료를 선언하지 않음. 목표는 실제 다음 계단 방향.
7.  마지막 단 이전·몸체 일부 미진출·반복된 오래된 pose로 도착하지 않음.
8.  관측 지연, 거절, epoch 변경, 취소, 통신 실패와 명령 소유권.
9.  정지 목표가 현재 추정값을 따라 이동하지 않음. 새 명령과 기존 대기 보정이 경쟁하지 않음.
10. 단일/연결 phase\_test의 허용 단계·단계별/전체 시간·취소 처리. 최종 단계까지 검사해도 정상 도착·4층 전환으로 전파되지 않음. 정상 임무 완료 때만 기존 미션·층 처리가 연결됨.

실패한 시험을 통과시키기 위해 실제 경계를 넓히거나 완료 높이를 낮추는 방식은 사용하지 않는다. 정상 주행을 막는 제약은 원인과 영향을 분리해 좁힌다.

## 10\. 수정 파일과 완료 산출물

| 범위                             | 예정 변경                                      | 변경 이유                  |
| ------------------------------ | ------------------------------------------ | ---------------------- |
| 기존 `supervisor.py`             | 첫 구간 모드 응답 처리·명령 이력, 단계별 시험 예산, 필요 시 전환 순서 | 시작 시점·실기 시험·상태 전환의 일관성 |
| 기존 `stair_feedback.py`         | 경계·완료 조건, 필요 시 연결 구역 검사, 제한 원인 진단          | 실제 계단 진행과 제어 판단 연결     |

| 기존 `ros_lidar.py`·RViz 설정      | 설정 출처, 경계 여유·실패 원인 표시                      | 왜 움직이거나 멈췄는지 바로 확인     |
| 기존 시험 요청 파싱·설정 검증              | 선택적인 from\_entry, 단계별/전체 예산 검증             | 기존 단일 시험과 호환되는 연결 시험   |
| 관련 시험·실행 안내                    | 위 회귀 사례와 기록 절차                             | 재현·재시작·복구 가능성 확보       |

진입 자동 정합에 새 경로 기준이 필요하면 기존 `entry_reference`·`capture_entry` 경로를 활용한다. 자동 정합이 모호할 때만 사용자의 위치 지정 경로를 이용하며, 임의의 위치를 알려진 진입점으로 취급하지 않는다. 3층 임의 출발 NAV의 AMCL 초기 위치 선택은 기존 자동/수동 기능을 유지하고 마지막 통합 시험에서 확인한다.

각 구현 묶음의 결과물은 변경 diff, 설정 출처와 해시, 회귀 결과, 경계/단계 RViz 화면, 실제 시험 명령과 BAG·상태 로그다. 임시 분석 파일·프로세스는 정리하고 재현에 필요한 결과만 보존한다.

**오프라인 완료:** 추적 보존, 시작 버그 수정 검증, 공통 계단 좌표와 단계별 경계 검증, 실행 설정 연결까지. **실기 완료:** 첫 구간부터 도착·대기·다음 명령까지 실제 반응 확인. **전체 시나리오 완료:** 3층 NAV→계단→4층 맵/상태/알림 일치까지.

## 11\. 사용자에게 필요한 정보와 남는 한계

지금 단계에서 이미 제공한 기체·센서·계단 치수를 다시 요청할 필요는 없다. 먼저 기존 자료로 진행한다. 점군에서 보이지 않는 계단 경계나 실제 실행 환경의 불일치가 확인되면 해당 항목만 구체적으로 질문한다.

실기 단계에서는 로봇을 진입 평지에 배치하고 조종기 회수 절차를 사용할 수 있는 시험 시점을 맞추면 된다. 현재 전원·로봇 위치는 확인하지 않았으며, 계획 작성 중에는 로봇에 명령을 보내지 않았다.

**계획의 우선순위는 확정됐지만, 현재 전체 계단 주행 성공과 최소 물리 제약은 UNVERIFIED다.** 예상 개선율이나 완료 시간을 수치로 약속하지 않는다. 가장 먼저 확정할 것은 실제 계단 경계·시작 위치와 현재 상태 판정의 불일치 원인이며, 그 결과가 경로 설정만의 수정인지 제어 조건까지의 수정인지를 결정한다.
