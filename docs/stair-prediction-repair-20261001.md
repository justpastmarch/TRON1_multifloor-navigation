# 계단 예측·복구 수정 v15 — 2026-10-01

기존 StairFeedback 내부의 복구·구간 인계·마지막 단 처리와 진단을 수정했다. 새 ROS 노드나 supervisor phase는 없다. 정책 식별자는 `2026-10-01-continuity-v15`다. 기존 LiDAR 정합 알고리즘과 WebSocket 변환은 유지한다.

**적용 범위:** 복구·인계 수정은 다음 스택 실행부터 사용한다. 새 물리 응답 예측기는 구현했지만 운영 설정은 `motion_prediction.mode: shadow`, `commissioned: false`다. 따라서 계단 미래 경로를 판단하는 운영 예측식은 아직 기존 명령 스케일 모델이다. 이번 변경을 근본 예측 문제의 실장비 해결 완료로 표현하면 안 된다.

OBSERVED는 소스·오프라인 실행에서 확인, INFERRED는 개선 효과의 추론, UNVERIFIED는 실물 확인이 필요한 항목이다. S/M 등급은 정성적 영향도이며 성공확률이 아니다. S2는 경계 대응 오판 가능성, S3은 밀림·경계 이탈에 따른 물리 위험 가능성, M4는 미션 중단의 영향이다. TUNE은 판정 방식·시간 예산 조정, NARROW는 불필요하게 넓은 차단 조건의 적용 범위 축소다.

계단 상승 요청은 기존 내부값 0.55→로봇 전진 입력 1을 사용하며 계단참은 기존 저속 설정이다. 차체, 바깥 구역, 센서 epoch, 사용자 interrupt, 통신 실패 조건을 삭제하지 않았다. 최소 제약의 실장비 증명 없는 항목은 KEEP로 판정하지 않았다.

마지막 단의 점군은 정합에 사용한 축소 점군을 기존 측위 프로세스에서 전달한다. 정합 입력·결과 계산은 바뀌지 않는다. `control_geometry_points: true`는 최대 5,000점 전달을 켜는 설정이다. 20cm voxel 간격에서도 판정 가능한 공간 범위를 사용한다. 점 20개를 요구하는 초기 구현은 실제 밀도와 맞지 않아 제거했다. 최소 6개의 서로 다른 공간 셀, 진행 방향 25cm·폭 방향 15cm 분포, 목표 평지 높이 ±4cm, 몸체 높이 부족 22cm 이하를 요구한다. 한 프레임이나 일렬로 몰린 점으로는 재개하지 않는다. 이 조건의 실물 검출률과 오검출률은 아직 UNVERIFIED다.

28cm는 다음 관측에서 집계하는 이동 예산이며 물리적인 정지거리 보장은 아니다. 0 명령도 물리적 위치 유지가 아니다. 추가 상승이 모순되거나 관측이 사라지면 기존 인계 경로로 돌아가며 평지 위치 유지 입력을 계단 중간에 임의 적용하지 않는다.

## 예측기 구현과 활성화 조건

새 `motion_prediction.py`는 실제 LiDAR 이동 추세와 gyro 회전율에서 시작한다. 원본 관측 위치·시각을 보존하고, 관측 나이만큼 위치를 별도로 전파한다. 전진 요청과 조향 요청에 대한 응답 지연·gain 구간, 속도·방향 오차를 포함한 여러 후보 운동을 계산한다. **0 요청에도 잔류 이동이 남는다.**

운영 비교는 한 개의 비동기 작업으로만 실행하며 새 관측을 무한 대기열에 넣지 않는다. 제어 잠금 안에서 비교 계산 종료를 기다리지 않는다. 비교 결과에는 사용 관측 sequence·시각·가정한 요청을 남긴다. 현재 송신 명령이나 해당 시점의 주행 허가 판정으로 표시하지 않는다. 운영 비교에서는 변위 예측만 계산하고, 전체 구역 허가 검사는 오프라인 또는 보정된 제어 모드에서 수행한다.

실제 제어 모드는 다음을 구현했다. 명시적으로 보정된 모델만 켤 수 있고, 관측 부족·허용 전파 나이 초과 시 기존 모델로 조용히 통과시키지 않는다. 복귀 조향과 지연 관측 경로도 새 예측으로 검사한다. 확인한 후보를 낮은 입력의 미검사 후보로 바꾸는 우회 경로는 차단했다. 마지막 평가 후보와 현재 송신 명령은 진단에서 구분한다.

**운영 모델의 활성화는 남아 있다.** 현재 YAML의 gain 구간·응답 지연·오차 예산은 비교용 가설이며 실측 보정값이 아니다. 이를 `commissioned: true`로 바꾸지 않았다. 제어 모드의 구현과 합성 시험은 물리 응답 범위를 증명하지 않는다. 여러 응답 가설을 표본 검사하는 모델도 모든 물리 운동이나 연속 gain 값을 엄밀하게 포함한다는 인증이 아니다.

필요한 남은 근거는 자동 입력/조이스틱/관측 시각을 대조한 구간별 응답 보정과 별도 실행에서의 검증이다. 입력 1의 평균 변위를 실제 최대 속도로 채택하지 않는다. 보정용 BAG과 검증용 BAG을 기록 전체 단위로 나누고, 실제 단수·경계·수동 개입 시각은 외부 영상/실측으로 대조한다.

합계 416개는 오프라인 소프트웨어 테스트 수이며 실제 416회 주행을 뜻하지 않는다. ROS fake 장비도 계단의 물리 응답을 대체하지 않는다.

9월 30일 BAG에서 추출한 124개의 상승 진단 tick을 v14와 v15로 고정 관측 재생했다. 둘 다 이 추출 범위 내 terminal fault가 없고 0 명령 tick은 11개였다. 따라서 **이 재생에서 중단이 줄었다는 결과는 없다.** 실제 첫 fault 상세는 BAG 종료 뒤 UI가 보존한 별도 기록이므로, 추출 범위에 없다는 사실을 완주 성공으로 계산하지 않는다. 재생은 raw 점군·전체 IMU 콜백을 갖춘 원래 40Hz 실행의 완전한 재현도 아니다.

비교 계산을 제어 경로에서 기다리던 초기 구현은 재생 계산시간 95백분위가 약 181ms로 증가해 제거했다. 비동기·벡터화 후 기록된 한 비교에서는 v14 약 24.3ms, v15 약 24.9ms였다. 이는 이 PC의 함수 실행 측정이며 WebSocket·LiDAR·ROS를 포함한 실시간 보장이나 현장 지연 개선 증거가 아니다. 원시 결과ㄹ는 `replay-comparison.json`에 보존한다.

독립 검토가 지적한 정보 없는 모델 fallback, 복귀 조향의 모델 우회, 저밀도 점군 조건, 제어 경로의 비교 지연, 오래된 후보 진단을 수정하고 관련 회귀를 추가했다. 검증 독립성 점검: 과거 경로에 새 명령을 계산한 결과를 그 명령으로 실제 움직인 결과라고 해석하지 않았다.

## 적용 및 남은 현장 확인

원래 저장소에 기존 파일 수정과 순수 계산 모듈·회귀 파일을 반영했고, 반영한 파일들의 해시가 검토본과 일치함을 확인했다. 실행 중 노드를 자동 재시작하거나 주행·STAIR 전환 명령을 보내지 않는다. 다음 정상 스택 실행에서 정책 식별자를 확인한다. 설정 유효성 `configured: true`는 완주 인증이 아니다.

UI는 최초 중단 원인을 보존하고 예측 재관측·측정 경계 여유·높이 불일치·센서 대기를 설명한다. 예측 비교가 진행 중인 사실도 표시한다. 기존 테스트 녹화의 실패 후 기록 유지 동작을 사용한다.

**Mobility verdict:** 복구·인계 조건의 동작은 오프라인 OBSERVED, 실제 중단 감소와 완주율은 UNVERIFIED. **Safety verdict:** 계단 동역학·위치 오차·밀림·마지막 단 추가 상승은 실물 확인이 남아 UNVERIFIED. 특히 근본 예측기 운용 전환은 완료되지 않았다.

작업 전 수정본의 사본·해시와 Git 상태를 보존했고 원래 파일의 내용이 작업 중 바뀌지 않았음을 확인한 뒤 적용했다. 원래 BAG과 이전 사용자 변경을 덮어쓰거나 되돌리지 않았다. 보고서·테스트/재생 코드·결과·변경 전 사본은 재현 산출물로 보관하며 편집용 임시 스크립트와 문법 확인 임시 파일은 정리한다. Git 차이는 이번 코드·설정·테스트·문서·UI 수정만 추가한 범위로 확인한다. 커밋·푸시는 수행하지 않는다.
