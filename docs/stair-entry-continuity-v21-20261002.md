# 진입 대기 연속성 수정 v21

## 변경 결과
기존 corridor 진입 방식을 쓰는 3→4층 및 5층→RF 경로에서 VERIFY_ENTRY가 정지 안정화를 기다리지 않는다. 새 관측의 진입영역·높이와 기존 자세·입력 신선도 조건을 확인하면 ALIGN으로 넘긴다. ALIGN의 방향 조건과 상승 전 전체 여유 조건은 유지한다. 기존 노드/FSM 안의 정책 변경이며 새 상태나 노드를 추가하지 않았다.

진입의 전체 여유는 기존 12cm(기준 위치 불확실성 10cm + 추가 여유 2cm)다. VERIFY_ENTRY는 기본 10cm 범위를 확보한 경우에도 정렬로 넘길 수 있다. ALIGN에서 추가 여유가 부족하면 기존 방향 보정의 회전량을 한도 내에서 검사한다. 차체의 예측 회전 궤적이 기본 범위를 지키고, 표본 여유가 시작값보다 작아지지 않으며 끝에서 증가하는 후보만 허용한다. 전진/후진이나 반대 방향의 임의 회전을 추가하지 않는다. 복구 가능한 후보가 없으면 기존 실패 처리가 남는다. 모든 위치에서 복구됨을 보장하는 변경은 아니다.

각속도 한도 0.2rad/s와 변화율 0.3rad/s², 기존 높이/자세/입력 조건, 계단참 v20 경로, 상승 속도 설정은 변경하지 않았다. legacy 경로의 정지 조건, 도착 안정화, 제어권 복구 조건도 유지한다. 이번 변경은 하드웨어 밀림을 능동적으로 붙잡는 위치 유지 제어를 구현한 것이 아니다.

## 독립 검토와 남은 한계
sip/shower 검토에서는 회전 검사에 대한 ‘단조 증가’ 해석을 경계했다. 실제 코드는 각 표본이 시작 여유보다 낮지 않고 마지막이 증가하는지를 검사하며, 매 표본이 직전보다 커야 한다는 뜻은 아니다. 표본 사이에는 별도의 전체 회전 검사로 기본 범위를 보호한다. 예측 기하가 물리적 밀림을 보장하지 않는다는 점을 명시했다.

검토자가 제기한 후보 평가의 부작용과 좌표계 가정은 코드에서 확인했다. `_limit_command`는 후보 평가 중 명령 이력을 갱신하지 않으며, position/support는 같은 관측에서 나온 평면 좌표다. VERIFY_ENTRY는 0 명령을 유지하므로 일반 진입 전이 직후의 명령 이력도 0이다. 다른 명령 이력에서 병진이 남으면 복구 후보를 거부하는 조건은 유지했다.

mandela 검토: 정책 설계자와 시험 작성자가 같고, 입력 자세도 해당 추정기의 출력이므로 이를 독립적인 물리 성능 검증으로 부르지 않는다. 코드 회귀/기록 입력 비교와 실주행을 분리했다. factchk 범위의 하드웨어 고장 단정이나 외부 ROS API 동작 주장은 추가하지 않았다. ssotize 읽기 점검에서는 진입 판정의 원본이 stair_feedback.py임을 확인했고 기존 기록 문서는 당시 동작의 이력으로 보존했다. 이 문서는 변경 기록이므로 전후 비교를 유지했다. 이식성 주장이 없어 detool은 생략했다.
