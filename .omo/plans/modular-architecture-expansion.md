- Require one explicit YAML `root` expression, always an `all` node, as the sole source of condition truth. Every `required` condition appears exactly once as a direct root member; every `optional` condition appears exactly once below one explicit root optional subtree composed from `all`, `any`, and `quorum`; if no optional conditions exist, the optional subtree is absent; `ignored` conditions are evaluated/traced but absent from `root`. Changing a mode may require updating expression membership in the same YAML edit, but never Python code.
- Evaluate only that explicit acyclic root expression. Do not synthesize an implicit required gate or add a second prerequisite/procedural truth gate. Reject unknown condition/group/producer IDs, a non-`all` root, expression cycles, wrong required placement, duplicate/unreachable optional leaves, ignored leaves referenced by root, and invalid quorum bounds.
- Preserve the existing epoch, monotonic freshness, future/stale rejection, dwell reset, terminal timeout, and immutable trace behavior while replacing flat string/`optional_count` evaluation with the explicit policy expression.
- Keep producers observation-only: capability-owned producer functions receive immutable snapshots and return typed evidence. They never publish, call a service/action, open a socket, execute `curl`, mutate runtime state, or decide the transition.
- Keep command handling outside the condition engine and inside the existing stair command stream/transport modules. Each existing stream-loop iteration selects zero when the last valid command is stale; nonfinite input is rejected and replaces the current command with zero; cancellation and normal shutdown perform the existing best-effort zero close while connected; WebSocket errors enter `FAULT`, stop the loop, and require process restart rather than hidden reconnect. Add no safety node, watchdog thread, command-guard state machine, delivery acknowledgement model, or extra recovery layer.
- Keep one-shot HTTP failures capability-local. The automatic-door example documents an optional future `door_adapter` node that performs a bounded fixed-argument HTTP/`curl` operation and publishes state; request acceptance and physical door-open confirmation are separate conditions. It is not deployed in the initial runtime.
